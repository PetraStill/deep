### Огляд задач комп'ютерного зору

Комп'ютерний зір (Computer Vision, CV) — одна з найважливіших галузей штучного інтелекту, яка спрямована на те, щоб машини могли «бачити» і розуміти візуальну інформацію так само, як це роблять люди.

| Задача | Що робить | Приклад застосування |
|---|---|---|
| **Класифікація зображень** | Визначає, до якого класу належить зображення | Медична діагностика (рентгенограми), розпізнавання рослин, маркування фотографій |
| **Детекція об'єктів** | Визначає клас об'єкта **та** його розташування (bounding box) | Відеоспостереження, автономні авто (пішоходи, дорожні знаки), відстеження товарів |
| **Сегментація зображень** | Розділяє зображення на сегменти — кожен піксель отримує клас | Медицина (виявлення патологій), аналіз супутникових зображень, робототехніка |
| **Відстеження об'єктів** | Безперервне визначення положення об'єкта у кожному кадрі відео | Спортивний аналіз (гравці, м'яч), AR (розширена реальність), відеоспостереження |
| **Відновлення 3D-сцени** | Реконструкція тривимірної структури з 2D-зображень | Картографія, архітектура, VR/відеоігри |

> **Семантична vs інстанційна сегментація:**
> - **Семантична** — визначає, до якого класу належить кожен піксель (усі машини = один клас)
> - **Інстанційна** — визначає окремі екземпляри (машина №1, машина №2, …)

### Що таке зображення для комп'ютера?

Зображення можна уявити як **сітку крихітних точок** — **пікселів**. Кожен піксель несе інформацію про колір та інтенсивність. Цю інформацію можна представити математично за допомогою **матриць** (двовимірних масивів чисел).

### Чорно-білі зображення (Grayscale)

У чорно-білих зображеннях кожне значення пікселя — це **один число**, яке представляє відтінок сірого:

| Значення | Колір |
|---|---|
| **0** | Чорний |
| **128** | Сірий (середній) |
| **255** | Білий |

Наприклад, зображення 3×3 у відтінках сірого:

```
⎡  0   128  255 ⎤
⎢ 64   192   32 ⎥
⎣255   128    0 ⎦
```

> **Перед запуском коду** не забудь імпортувати бібліотеки — вони потрібні для всіх прикладів цього конспекту:
>
> ```python
> import numpy as np
> import matplotlib.pyplot as plt
> ```

```python
# Візуалізуємо матрицю 3×3 як чорно-біле зображення
data = [[0, 128, 255], [64, 192, 32], [255, 128, 0]]
plt.imshow(data, cmap='gray')  # cmap='gray' — відтінки сірого
plt.show()
```

| `plt.show()` | Показує фігуру на екрані | — |

### Кольорові зображення (RGB)

Кольорові зображення представлені за допомогою колірної моделі **[RGB](https://uk.wikipedia.org/wiki/RGB)** (Red, Green, Blue). Кожен піксель описується **трьома значеннями** — по одному для кожного кольорового каналу (від 0 до 255).

Для RGB-зображення використовуються **три матриці**, по одній для кожного каналу:

**Червоний канал:**
```
⎡ 255   0 ⎤
⎣ 128  64 ⎦
```

**Зелений канал:**
```
⎡ 128  255 ⎤
⎣  64    0 ⎦
```

**Синій канал:**
```
⎡   0  128 ⎤
⎣ 255  192 ⎦
```

```python
# Візуалізуємо RGB-зображення 2×2 з трьох каналів
data = [[[255, 0], [128, 64]], [[128, 255], [64, 0]], [[0, 128], [255, 192]]]
data = np.moveaxis(data, 0, -1)  # переставляємо осі: [3, 2, 2] → [2, 2, 3] — (H, W, C)
plt.imshow(data)
plt.show()
```

| Рядок | Що робить | Параметри |
|---|---|---|
> **Скорочення розмірностей:** **N** = batch size (кількість зображень у батчі), **H** = Height (висота), **W** = Width (ширина), **C** = Channels (канали). Одне зображення: `[H, W, C]` (NumPy/PIL) або `[C, H, W]` (PyTorch — канали першими). Батч зображень: `[N, C, H, W]` — наприклад, `[32, 3, 64, 64]` = 32 RGB-зображення 64×64.

| Рядок | Що робить | Параметри |
|---|---|---|
| `np.moveaxis(data, 0, -1)` | Переставляє осі масиву | `0` — яку вісь переміщуємо (канали); `-1` — куди (в кінець). Результат: `[3, 2, 2]` → `[2, 2, 3]` (H, W, C) |
| `plt.imshow(data)` | Відображає масив як кольорове зображення | Без `cmap` — matplotlib автоматично інтерпретує останній вимір як RGB |

**Виведення:** [Візуалізація RGB-матриці](images/rgb_matrix_2x2.jpg)

#### Чому матриці саме 2×2?

Наше зображення має розмір **2 × 2 пікселі**, тому кожен канал теж є матрицею **2 × 2**:

```
2 рядки × 2 стовпці = 4 пікселі
```

Наприклад, червоний канал:

```
255   0
128  64
```

Це означає:
- верхній лівий піксель: R = 255
- верхній правий: R = 0
- нижній лівий: R = 128
- нижній правий: R = 64

По дві цифри в рядку — бо ширина зображення **2 пікселі**. І рядків теж 2 — бо висота **2 пікселі**.

**Ключова ідея:** матриця каналу показує інтенсивність цього одного кольору в кожній позиції зображення.

#### Як реконструюється колір?

Для кожного пікселя беремо по одному значенню з R, G і B та комбінуємо їх.

Наприклад, нижній правий піксель:

```
R = 64
G = 0
B = 192
```

Його колір: `[64, 0, 192]` → **фіолетовий**.

Верхній лівий піксель: (R=255, G=128, B=0) → **помаранчевий**.

### Роздільна здатність зображення

Розміри зображення визначаються **шириною** (кількість стовпців) і **висотою** (кількість рядків). Роздільна здатність зазвичай описується як ширина × висота:

| Роздільна здатність | Кількість пікселів | Назва |
|---|---|---|
| 1920 × 1080 | ≈ 2 мільйони | Full HD |
| 3840 × 2160 | ≈ 8 мільйонів | 4K UHD |
| 64 × 64 | 4 096 | Наш датасет SIGNS |

> **Ключовий висновок:** зображення для нейромережі — це тензор (багатовимірний масив). Grayscale → матриця `[H, W]`, RGB → тензор `[3, H, W]` або `[H, W, 3]` (залежно від бібліотеки).

### Крок 3. Перегляд прикладів зображень

**Що робимо:** переглядаємо зразки зображень з навчальної та тестової вибірки.

**Навіщо:** перед моделюванням завжди потрібно «побачити» дані — зрозуміти, що саме модель буде аналізувати, чи є дисбаланс класів, чи достатній розмір зображень.

```python
# Переглядаємо кількість зображень по класах та виводимо приклади з train
for s in splits:
    files = [f for f in os.listdir(f"{data_path}{s}_signs") if f.endswith('.jpg')]
    print(f'{len(files)} images in {s}')

    files = [f.split('_', 1) for f in files]  # розділяємо ім'я: "0_IMG.jpg" → ["0", "IMG.jpg"]

    files_by_sign = defaultdict(list)          # групуємо файли по класах
    for k, v in files:
        files_by_sign[k].append(v)

    for k, v in sorted(files_by_sign.items()):
        print(f'Number of examples for class {k}:', len(v))

        if s == 'train':
            random.seed(42)  # фіксуємо seed для відтворюваності

            imgs_path = random.sample(v, 4)  # випадково обираємо 4 зразки
            imgs_path = [os.path.join(data_path, f'{s}_signs/{k}_{p}') for p in imgs_path]

            imgs = [cv2.imread(p) for p in imgs_path]                  # читаємо зображення (BGR)
            imgs = [cv2.cvtColor(img, cv2.COLOR_BGR2RGB) for img in imgs]  # конвертуємо BGR → RGB

            fig = plt.figure(figsize=(7, 2))
            grid = ImageGrid(fig, 111, nrows_ncols=(1, 4))  # сітка 1×4 для 4 зображень
            for ax, img in zip(grid, imgs):
                ax.imshow(img)

            fig.suptitle(f'Class {k}, {s.capitalize()} split')
            plt.show()
```

**Пояснення ключових рядків:**

| Рядок | Що робить | Навіщо |
|---|---|---|
| `os.listdir(...)` | Отримує список файлів у директорії | Щоб знати, які зображення є в наборі даних |
| `f.endswith('.jpg')` | Фільтрує тільки JPG-файли | У директорії можуть бути інші файли (наприклад, .DS_Store) |
| `f.split('_', 1)` | Розділяє ім'я файлу по першому `_` | Перший символ — клас (0–5), решта — ім'я файлу |
| `defaultdict(list)` | Словник, де нові ключі автоматично ініціалізуються порожнім списком | Не потрібно перевіряти `if key in dict` перед додаванням |
| `cv2.imread(p)` | Читає зображення з диска за допомогою OpenCV | Повертає зображення як NumPy масив у форматі **BGR** |
| `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)` | Конвертує BGR → RGB | OpenCV використовує **BGR** (Blue-Green-Red), а matplotlib очікує **RGB** |
| `ImageGrid(fig, 111, nrows_ncols=(1, 4))` | Створює сітку 1 рядок × 4 стовпці для відображення зображень | Зручно показати кілька прикладів одного класу поруч |

> **Навіщо конвертувати BGR → RGB?**
>
> І RGB, і BGR — це ті самі 3 канали, просто записані в різному порядку.
>
> Один піксель червоного кольору в RGB:
> ```
> RGB = [255, 0, 0]   →   R=255, G=0, B=0
> ```
>
> А OpenCV той самий піксель зберігає як:
> ```
> BGR = [0, 0, 255]   →   B=0, G=0, R=255
> ```
>
> Тому `cv2.imread(p)` може повернути піксель `[10, 50, 200]`, де OpenCV розуміє це як B=10, G=50, R=200. Але `matplotlib` вважатиме, що R=10, G=50, B=200 — і покаже **неправильні кольори**.
>
> `cv2.cvtColor(img, cv2.COLOR_BGR2RGB)` просто переставляє канали:
> ```
> [B, G, R] → [R, G, B]
> [10, 50, 200] → [200, 50, 10]
> ```
>
> Після цього `plt.imshow(img)` показує правильні кольори.
>
> **Чому OpenCV так робить?** Це історична особливість — багато старих систем обробки зображень використовували порядок BGR, і OpenCV зберіг цю традицію.
>
> **Ключова думка:** дані не змінюються по суті — змінюється тільки порядок трьох каналів.

#### Що робить цей блок коду?

Тут **ніякого аналізу чи навчання моделі не відбувається**. Код лише дивиться, які дані ми маємо, і показує кілька прикладів. Це типовий **data exploration / sanity check** — «подивімося, чи правильно завантажили дані, скільки класів, чи збалансовані вони, і як взагалі виглядають картинки».

**Покроковий алгоритм:**

```
папки train/test
        ↓
знайти всі .jpg
        ↓
витягнути class з filename
        ↓
згрупувати за class
        ↓
порахувати кількість
        ↓
взяти випадкові 4
        ↓
відкрити через OpenCV
        ↓
BGR → RGB
        ↓
показати через matplotlib
```

**Ключові деталі:**

- Код виводить не перші 4, а **випадкові 4 зображення** кожного класу: `random.sample(v, 4)`. Завдяки `random.seed(42)` вибір **відтворюваний** — при повторному запуску виберуться ті самі картинки.

- **Назви файлів — це мітки класів.** Наприклад, `0_IMG_5975.jpg` → клас `0`. Рядок `f.split('_', 1)` перетворює `"0_IMG_5975.jpg"` на `["0", "IMG_5975.jpg"]`, після чого `files_by_sign[k].append(v)` групує картинки за класами.

- Цикл проходить і `train`, і `test`, але картинки показує **тільки для `train`**, бо є перевірка `if s == 'train':`.

- Конвертація BGR → RGB — **виключно технічна підготовка для правильного відображення кольорів** (див. пояснення вище). Без неї фото відкриється, але синє може виглядати червоним і навпаки.

**Виведення:** [Приклади класів 0, 1, 2](images/dataset_class_0_1_2.jpg) | [Приклади класів 3, 4, 5](images/dataset_class_3_4_5.jpg) | [Тестова вибірка — 120 зображень](images/dataset_test_info.jpg)

## ЧАСТИНА 3. ЗГОРТКОВІ НЕЙРОННІ МЕРЕЖІ (CNN)

### Що таке CNN і навіщо вона потрібна?

Нейронні мережі, які найкраще справляються із задачами комп'ютерного зору, називаються **згортковими нейронними мережами** (Convolutional Neural Network, CNN / ConvNet).

CNN складається з **двох частин:**

**Схема:** [Архітектура CNN: Base + Head](images/cnn_base_head.jpg)

| Частина | Назва | Що робить | Аналогія |
|---|---|---|---|
| **Base** (згорткова основа) | Convolution Base | Витягує візуальні ознаки із зображення (лінії, текстури, форми) | «Очі» — бачить і аналізує |
| **Head** (класифікаційна голова) | Dense Head | Перетворює ознаки у фінальне передбачення класу | «Мозок» — приймає рішення |

**Мета мережі під час навчання — навчитися двом речам:**
1. Визначити, **які ознаки** витягти із зображення (**base**)
2. Визначити, **який клас** з якими ознаками поєднується (**head**)

**Схема:** [CNN: витягування ознак різних рівнів](images/cnn_feature_maps.jpg)

> **Візуальні ознаки** — це лінія, колір, текстура, форма, патерн або їх складна комбінація. На відміну від табличних даних, де ознаки — це числові стовпці, в зображеннях ознаки — це візуальні патерни.

---

### Згортковий шар (Convolution Layer)

Роль згорткового шару — **витягувати ознаки із зображення**. Він не просто дивиться на окремі пікселі, а шукає локальні закономірності: краї, лінії, кути, текстури, а у глибших шарах — складніші частини об'єктів.

Механізм:

```
зображення
      ↓
фільтр 3×3 проходить по ньому
      ↓
у кожній позиції рахується відповідь
      ↓
утворюється feature map
```

Якщо фільтр добре "реагує" на певну ознаку, у відповідній частині feature map буде велике значення. Шари працюють ієрархічно:

```
вхідне фото кота
      ↓
перші Conv-шари → краї, контури
      ↓
наступні Conv-шари → вуха, очі, шерсть
      ↓
глибші шари → складні частини образу кота
```

Тобто **згортковий шар перетворює сирі пікселі на корисні ознаки, за якими мережа далі може розпізнавати об'єкти.**

#### Основні компоненти

| Компонент | Що це | Як працює |
|---|---|---|
| **Ядро згортки (Kernel / Filter)** | Невелика матриця (зазвичай 3×3 або 5×5) | Ковзає по зображенню, виконуючи поелементне множення |
| **Крок (Stride)** | Наскільки ядро зміщується за раз | Stride=1 → рухається на 1 піксель, stride=2 → на 2 пікселі |
| **Заповнення (Padding)** | Додаткові пікселі навколо зображення | Зберігає або змінює розмір вихідного зображення |

> **Kernel vs Filter:** у навчальних матеріалах ці слова часто вживають взаємозамінно, але є нюанс. Для grayscale-зображення kernel = filter = одна матриця 3×3 ваг. Для RGB один **filter** складається з трьох **kernel**-матриць (по одній на канал R, G, B), і разом вони створюють одну feature map. Тобто **kernel** — ваги для одного каналу, **filter** — весь набір kernel-ів.

#### Як працює згортка — покроково

Розглянемо операцію згортки зображення розміром **5×5** з ядром **3×3**:

**Ядро згортки:**
```
⎡ 1  0  1 ⎤
⎢ 0  1  0 ⎥
⎣ 1  0  1 ⎦
```

При stride=1 ядро зміщується 9 разів, кожного разу виконуючи **поелементне множення** між ядром і частиною зображення, на яку воно накладається. Результати множення **сумуються** і записуються у вихідну матрицю (згорнуту ознаку).

**Анімація:** [Операція згортки: 5x5 зображення з 3x3 ядром](images/convolution_operation.gif)

**Алгоритм:**
1. Ядро накладається на ліву верхню частину зображення
2. Виконується поелементне множення ядра на фрагмент зображення
3. Результати множення підсумовуються → одне число у вихідній матриці
4. Ядро зміщується вправо на `stride` пікселів
5. Коли досягнуто правого краю — ядро переміщується вниз і починає з лівого краю
6. Процес повторюється до повного проходу зображення

#### Як stride впливає на розмір виходу?

Що більший `stride`, то **менше позицій встигає зайняти ядро** на зображенні.

Наприклад, зображення шириною 5 пікселів і ядро 3 пікселі:

При `stride = 1` ядро може стати так:

```
позиція 1: [1 2 3]
позиція 2:   [2 3 4]
позиція 3:     [3 4 5]
```

Отже маємо **3 результати**.

При `stride = 2`:

```
позиція 1: [1 2 3]
позиція 2:     [3 4 5]
```

Отже вже тільки **2 результати**.

Ядро робить менше "зупинок" → ми отримуємо менше значень у вихідній feature map.

**Формула для одного виміру без padding:**

```
output = ⌊(input − kernel) / stride⌋ + 1
```

Наприклад, для `input = 5`, `kernel = 3`:

| stride | Обчислення | Результат |
|---|---|---|
| 1 | (5 − 3) / 1 + 1 | **3** |
| 2 | (5 − 3) / 2 + 1 | **2** |

Тому **більший stride → менша вихідна карта ознак**.

---

### Типи padding

#### Valid Padding (без padding)

Ядро проходить **тільки** через ті пікселі, де воно повністю поміщається. Вихідне зображення **менше** за вхідне.

**Формула розміру виходу** (stride = 1):

```
Вихід = (n − k + 1) × (n − k + 1)
```

де `n×n` — розмір входу, `k×k` — розмір ядра.

**Приклад:** вхід 5×5, ядро 3×3 → вихід (5−3+1) × (5−3+1) = **3×3**

| Переваги | Недоліки |
|---|---|
| Не додаються зайві пікселі | Зменшення розміру → можлива втрата інформації |
| Зменшує розмір на ранніх етапах | Проблема для малих зображень з великими ядрами |

#### Same Padding

Padding додається так, щоб розмір виходу **залишався таким самим**, як у входу. Навколо зображення додаються нульові пікселі.

| Переваги | Недоліки |
|---|---|
| Зберігається розмір зображення | Нулі на краях можуть впливати на результат |
| Спрощує архітектуру (консистентні розміри) | — |

**Анімація:** [Valid padding vs Same padding](images/padding_types.gif)

### Реалізація згорткового шару в PyTorch

Згортковий шар реалізується функцією `nn.Conv2d()`. Її сигнатура (це **не код для виконання**, а лише опис параметрів):

```
nn.Conv2d(in_channels, out_channels, kernel_size, stride=1, padding=0)
```

**Параметри:**

| Параметр | Тип | Що означає | Приклад |
|---|---|---|---|
| `in_channels` | int | Кількість каналів входу | 3 (RGB) або 32 (після попереднього шару) |
| `out_channels` | int | Кількість фільтрів (каналів виходу) | 32, 64, 128 |
| `kernel_size` | int або tuple | Розмір ядра | 3 → ядро 3×3 |
| `stride` | int або tuple | Крок згортки | 1 (за замовчуванням) |
| `padding` | int або str | Кількість нульових пікселів навколо | 1 → same padding для ядра 3×3 |

**Розміри входу та виходу:**

Для вхідних даних розміром `(N, C_in, H, W)` вихід буде `(N, C_out, H_out, W_out)`:
- **N** — розмір батчу
- **C** — кількість каналів
- **H** — висота у пікселях
- **W** — ширина у пікселях

```python
# Приклад використання Conv2d з різними параметрами
input = torch.randn(20, 16, 50, 100)  # batch=20, channels=16, h=50, w=100

m = nn.Conv2d(16, 33, 3, stride=2)    # 16 каналів → 33 фільтри, ядро 3×3, крок 2
output = m(input)
output.shape  # torch.Size([20, 33, 24, 49])

m = nn.Conv2d(16, 33, (3, 5), stride=(2, 1), padding=(4, 2))  # прямокутне ядро + padding
output = m(input)
output.shape  # torch.Size([20, 33, 28, 100])
```

### Як пов'язані фільтри, канали та шари?

[Схема: Conv2d — фільтри, канали та потік даних між шарами](images/conv2d_filters_and_channels.png)

#### out_channels = кількість фільтрів

Параметр `out_channels` визначає, скільки різних фільтрів має шар. Кожен фільтр проходить по зображенню і створює свою **feature map**:

```
RGB image (3 канали)
        ↓
Conv2D, 32 фільтри
        ↓
32 feature maps (= 32 канали виходу)
```

Тому **наступний шар отримує на вхід стільки каналів, скільки фільтрів мав попередній шар:**

```python
conv1 = nn.Conv2d(3, 32, 3)     # RGB → 32 feature maps
conv2 = nn.Conv2d(32, 64, 3)    # 32 → 64 feature maps
conv3 = nn.Conv2d(64, 128, 3)   # 64 → 128 feature maps
```

Правило: `out_channels попереднього шару = in_channels наступного шару`.

#### Як виглядає один фільтр?

Для `nn.Conv2d(in_channels=3, out_channels=32, kernel_size=3)` один фільтр має розмір **3 × 3 × 3**:
- `3 × 3` — розмір ядра
- `× 3` — бо вхід має 3 канали (R, G, B)

Тобто один фільтр "дивиться" одразу на всі три канали:

```
R channel: [ 3×3 weights ]
G channel: [ 3×3 weights ]
B channel: [ 3×3 weights ]
```

А таких фільтрів **32** → 32 вихідні feature maps.

#### Що саме вчать фільтри?

**Фільтр — це набір ваг.** На старті ваги майже випадкові — фільтри спочатку нічого осмисленого не "знають". Під час навчання:

```
зображення
      ↓
фільтри дають feature maps
      ↓
модель робить prediction
      ↓
порівнюємо з правильною відповіддю → loss
      ↓
backpropagation показує, які ваги треба змінити
      ↓
optimizer трохи змінює ваги фільтрів
      ↓
(повторюється тисячі разів)
```

У результаті певний набір ваг може стати таким, що він сильно реагує на конкретний патерн. Наприклад, фільтр може навчитися мати ваги:

```
-1   0   1
-1   0   1
-1   0   1
```

Коли він накладається на область, де зліва темно, а справа світло — виходить сильна позитивна відповідь. Він "шукає вертикальний край" не тому, що хтось йому це сказав, а тому що **така конфігурація ваг виявилась корисною для зменшення loss**.

Фільтр не "розуміє" семантично, що таке край — він просто має ваги, які математично дають сильну активацію на певний патерн.

Поступово різні фільтри навчаються реагувати на різні ознаки:

| Глибина шару | Приклади ознак |
|---|---|
| Перші 32 фільтри | Краї, лінії, прості кольорові переходи |
| Наступні 64 | Кути, форми, текстури |
| Наступні 128 | Складніші частини об'єктів |

Ми **не кажемо наперед**, що саме має шукати кожен фільтр — вони самі навчаються. `out_channels=32` фактично означає: *«Я хочу, щоб цей шар навчився 32 різним способам аналізувати локальні ділянки зображення».*

#### Чи завжди фільтри вчать різне?

Жорсткої гарантії немає. Модель оптимізує loss, а не «різноманітність фільтрів». Тому кілька фільтрів можуть реагувати на дуже схожі патерни:

- один — на вертикальний край
- другий — на такий самий край, але з іншою товщиною або контрастом
- третій — на край у певній кольоровій комбінації

Іноді фільтри можуть майже дублювати один одного — це називають **redundancy** (надлишковість). У великих моделях це нормально. Саме тому існують техніки на кшталт **pruning**: можна прибрати малокорисні або дубльовані фільтри й інколи майже не втратити якість.

#### Чому саме 32, 64, 128?

Це **вибір розробника**, а не жорстке правило. Можна зробити `16 → 32 → 64` або `24 → 48 → 96`.

Степені двійки (32 = 2⁵, 64 = 2⁶, 128 = 2⁷) популярні тому, що вони **ефективні для GPU** — обчислення на відеокартах виконуються блоками, і розміри, кратні 8/16/32, краще використовують Tensor Cores.

Кількість фільтрів зазвичай **зростає з глибиною**, бо глибші шари мають виявляти більше різних складних ознак. `32` — поширений компроміс між здатністю знайти багато ознак, швидкістю роботи та кількістю параметрів.

---

### Що таке повнозв'язний (fully-connected) шар?

Повнозв'язний шар — це шар, де **кожен нейрон з'єднаний з усіма значеннями попереднього шару**. У PyTorch це `nn.Linear(...)`.

Наприклад, якщо на вході 4 значення, а fully-connected шар має 3 нейрони — кожен із 3 нейронів отримує всі 4 входи:

```
x1 ─┬──→ neuron 1
x2 ─┤
x3 ─┤
x4 ─┘

x1 ─┬──→ neuron 2
x2 ─┤
x3 ─┤
x4 ─┘

x1 ─┬──→ neuron 3
x2 ─┤
x3 ─┤
x4 ─┘
```

Тобто `nn.Linear(1000, 100)` — це 100 нейронів, кожен дивиться на всі 1000 входів = **100 000 ваг** (+ bias).

А у convolutional layer нейрон дивиться лише на локальну ділянку, наприклад `3×3`. Саме тому згорткові шари значно економніші для зображень.

### Переваги згорткового шару

| Перевага | Пояснення | Порівняння з повнозв'язним шаром |
|---|---|---|
| **Локальна зв'язність** | Кожен нейрон взаємодіє лише з невеликою частиною зображення (рецептивне поле) | Повнозв'язний шар з'єднаний з **усіма** пікселями → набагато більше параметрів |
| **Спільні ваги** | Одне ядро використовується для **всіх** частин зображення | Ті самі ваги виявляють однакові ознаки в різних частинах зображення |
| **Інваріантність до зсувів** | Розпізнає об'єкти незалежно від їх розташування | Кіт у лівому кутку = кіт у правому кутку |

> **Аналогія:** згортковий шар — це як лупа, яка систематично сканує зображення. Одна лупа (ядро) шукає горизонтальні лінії, інша — вертикальні, третя — кути. Разом вони створюють повну картину ознак.

#### Спільні ваги (weight sharing) детальніше

У звичайному `Conv2D` одне ядро `3×3` має один набір ваг і ковзає по **всьому** зображенню — всюди використовуються ті самі ваги.

Альтернатива — **locally connected layer** без weight sharing, де для кожної позиції зображення було б своє окреме ядро. Порівняємо для зображення `100 × 100` з ядром `3×3`:

| | Звичайна згортка | Без спільних ваг |
|---|---|---|
| Кількість ваг (1 фільтр) | 3 × 3 = **9** | 98 × 98 × 9 ≈ **86 000** |

Тому shared weights дають дві великі переваги:

1. **Набагато менше параметрів** — економія в тисячі разів.
2. **Інваріантність** — якщо фільтр навчився знаходити вертикальну грань, він знайде її будь-де на зображенні.

> CNN ніби каже: *«Мені не важливо, де саме знаходиться ця ознака. Якщо я вмію її розпізнати, я використаю той самий детектор по всьому зображенню».*

#### Інваріантність до зсувів детальніше

Якщо фільтр навчився знаходити вертикальний край, а потім цей край змістився — той самий фільтр усе одно його знайде, бо він ковзає по всьому зображенню з тими самими вагами:

```
|край|                       →           |край|
  ↑                                         ↑
фільтр знаходить тут              і тут також
```

CNN не прив'язує ознаку до конкретної координати (*«вертикальна лінія має бути тільки в x=20, y=50»*). Вона радше вчиться: *«якщо десь є така структура — я її розпізнаю»*.

Але повна незалежність від положення з'являється не від одного Conv2D, а завдяки комбінації:
- **convolution** — локальне виявлення ознак
- **pooling / stride** — зменшення просторового розміру
- **багато шарів** — від простих ознак до складних
- **data augmentation** — навчання на зміщених/повернутих версіях зображень

### Шар об'єднання (Pooling Layer)

Подібно до згорткового шару, шар об'єднання відповідає за **зменшення просторової розмірності** (висоти та ширини) feature maps. Це потрібно для:
- зменшення обчислювальної потужності, необхідної для обробки даних;
- виділення домінантних ознак.

#### Де pooling стоїть у мережі?

Зазвичай pooling йде **після згортки**:

```
вхідне зображення
      ↓
Convolution → feature maps (шукає ознаки: краї, лінії, текстури)
      ↓
Pooling → менші feature maps (стискає, зберігаючи найсильніші реакції)
```

Pooling не шукає нову ознаку так, як convolution. Він радше каже: *«У цій ділянці ознака була сильно присутня — залишимо це головне значення».*

Наприклад, після згортки маємо feature map `4×4`, робимо `MaxPooling 2×2`:

```
[1  5 | 3  2]        [5 | 3]
[2  3 | 1  0]   →    [8 | 6]
[8  1 | 6  4]
[0  2 | 3  5]
```

У кожному блоці `2×2` береться максимальне значення — зберігається найсильніша реакція на ознаку.

> Технічно pooling можна застосувати й до вхідного зображення, але в CNN його використовують після згорткових шарів. Сама згортка не обов'язково зменшує розмір (з `padding="same"` і `stride=1` розмір залишається тим самим), а pooling спеціально використовується для downsampling.

[Анімація: pooling 3×3 ковзає по згорнутому об'єкту 5×5](images/pooling_3x3_over_5x5.gif)

#### Приклад на числах: Max Pooling vs Average Pooling

Уявімо feature map `4×4` після convolution, вікно `2×2`, `stride=2`:

```
Feature map:          Розбиття на блоки:
1   2   8   6         [1  2] [8  6]
3   4   5   7         [3  4] [5  7]
9   1   2   3
6   5   4   8         [9  1] [2  3]
                      [6  5] [4  8]
```

**Max Pooling** — у кожному блоці залишаємо найбільше число:

```
[1 2]→4   [8 6]→8        Результат:  4  8
[3 4]     [5 7]                      9  8

[9 1]→9   [2 3]→8
[6 5]     [4 8]
```

*«Мене цікавить, чи була в цій ділянці сильна реакція на ознаку. Якщо була — залишаю найсильнішу».*

**Average Pooling** — у кожному блоці беремо середнє:

```
[1 2]→(1+2+3+4)/4=2.5        Результат:  2.5   6.5
[3 4]                                     5.25  4.25

[8 6]→(8+6+5+7)/4=6.5
[5 7]
```

*«Мене цікавить не найсильніша ознака, а яка в середньому активність у цій області».*

#### Різниця на одному блоці

```
[1  1]
[1  9]
```

| Метод | Результат | Інтерпретація |
|---|---|---|
| **Max Pooling** | **9** | «Тут десь була дуже сильна ознака» |
| **Average Pooling** | **3** | «У середньому ця область має активність 3» |

**Max Pooling = "знайди найсильніше"**
**Average Pooling = "опиши область у середньому"**

[Схема: Max Pooling vs Average Pooling на матриці 4×4 з вікном 2×2](images/pooling_types.png)

#### Max Pooling

- Зберігає найвиразніші ознаки, які найбільш інформативні для класифікації.
- Ігнорує менш виразні, але потенційно корисні ознаки.
- Частіше використовується у задачах, де важливі найяскравіші ознаки (наприклад, виявлення об'єктів).

#### Average Pooling

- Зберігає інформацію про середні значення ознак.
- Менший ризик втратити корисну інформацію порівняно з max pooling.
- Може зменшувати виразність ознак, оскільки значення усереднюються.
- Використовується у задачах, де важливі середні значення (наприклад, усунення шумів — image denoising).

> У CNN pooling зазвичай працює вже **не з самим RGB-зображенням, а з feature maps після convolution**.

#### Реалізація шару об'єднання в PyTorch

```python
input = torch.randn(20, 16, 50, 100)  # batch_size=20, channels=16, h=50, w=100

# Pooling з квадратним вікном 3×3, stride=2
m = nn.MaxPool2d(3, stride=2)
output = m(input)
output.shape  # torch.Size([20, 16, 24, 49])

# Pooling з прямокутним вікном (3, 2), stride=(2, 1)
m = nn.MaxPool2d((3, 2), stride=(2, 1))
output = m(input)
output.shape  # torch.Size([20, 16, 24, 99])
```

**Параметри `nn.MaxPool2d`:**

| Параметр | Тип | Що означає | Приклад |
|---|---|---|---|
| `kernel_size` | int або tuple | Розмір вікна pooling | `3` → вікно 3×3; `(3, 2)` → 3 по висоті, 2 по ширині |
| `stride` | int або tuple | Крок зміщення вікна | `2` → зміщується на 2 пікселі; `(2, 1)` → 2 по висоті, 1 по ширині |

> Зверніть увагу: pooling **не змінює кількість каналів** — тільки просторові розміри (H, W). Тому на вході 16 каналів → на виході теж 16.

### Класифікаційні шари (Classification Layers)

Після серії згорткових шарів та pooling CNN переходить від витягування ознак до прийняття рішення. Повна архітектура CNN складається з двох частин:

```
INPUT → [Conv + ReLU → Pooling] × N → Flatten → Fully Connected → Softmax → OUTPUT
         \_________________________/    \________________________________/
              FEATURE LEARNING                    CLASSIFICATION
```

[Схема: повна архітектура CNN — від вхідного зображення до класифікації](images/cnn_full_architecture.png)

#### Шар розгортання (Flatten Layer)

Flatten перетворює багатовимірний тензор (результат згорткових шарів і pooling) в **одномірний вектор**. Наприклад:

```
Feature maps після pooling:       Після flatten:
  ┌───────────┐
  │ 1  1  0   │                   [1, 1, 0, 4, 2, 1, 0, 2, 1]
  │ 4  2  1   │        →
  │ 0  2  1   │                   (9 значень в одному рядку)
  └───────────┘
  тензор 3×3
```

- Готує дані для повнозв'язних шарів, які очікують вхід у вигляді одномірного вектора.
- **Не має параметрів для навчання** — просто змінює форму даних.

[Схема: Flatten — розгортання матриці 3×3 у вектор 9×1](images/flatten_3x3_to_9x1.png)

#### Повнозв'язний шар (Fully Connected Layer)

Повнозв'язний шар складається з нейронів, **кожен з яких з'єднаний з усіма нейронами попереднього шару**. Кожне з'єднання має свою вагу, яка оновлюється під час навчання через зворотне розповсюдження.

Цей шар комбінує ознаки, виділені попередніми шарами, щоб отримати остаточний результат — наприклад, ймовірності класів у задачі класифікації. Після останнього fully connected шару зазвичай йде фінальна функція активації (Softmax для класифікації).

[Схема: Flattened Input → Fully Connected нейрони](images/fc_layer_neurons.png)

#### Весь шлях даних у CNN

```
Вхідне зображення (H × W × 3)
        ↓
Conv2D + ReLU → feature maps (витягування ознак)
        ↓
MaxPooling → зменшені feature maps
        ↓
... (ще Conv + Pool шари) ...
        ↓
Flatten → одномірний вектор
        ↓
Fully Connected (nn.Linear) → комбінування ознак
        ↓
Softmax / Log-Softmax → ймовірності класів
        ↓
Передбачення: клас 3 (наприклад, жест "три")
```

## ЧАСТИНА 4. АУГМЕНТАЦІЯ ЗОБРАЖЕНЬ (IMAGE AUGMENTATION)

### Навіщо потрібна аугментація?

Аугментація — це застосування **різних трансформацій** до вхідних зображень для створення нових варіантів навчальних даних.

| Ціль | Як аугментація допомагає |
|---|---|
| **Збільшення обсягу даних** | Створює нові зразки без збору нових даних — особливо корисно для невеликих наборів |
| **Поліпшення узагальнення** | Модель стає стійкішою до варіацій (освітлення, масштаб, кут зору) |
| **Запобігання overfitting** | Більша різноманітність даних знижує ризик перенавчання |

### Що таке `torchvision.transforms`?

`torchvision.transforms` — модуль бібліотеки **torchvision** з готовими перетвореннями для зображень:

```python
import torchvision.transforms as T  # T — коротке ім'я
```

Використовується і для **preprocessing**, і для **augmentation**:

```text
T.Resize(...)           ← preprocessing (уніфікація розміру)
T.RandomRotation(...)   ← augmentation (випадковий поворот)
T.ToTensor()            ← preprocessing (PIL Image → тензор)
T.Normalize(...)        ← preprocessing (нормалізація значень)
```

`T.Compose(...)` — застосовує перетворення **послідовно одне за одним**:

```python
transform = T.Compose([
    T.Resize((64, 64)),          # 1. привести до єдиного розміру
    T.RandomRotation(10),        # 2. випадковий поворот ±10°
    T.ToTensor(),                # 3. PIL Image → тензор [0, 1]
    T.Normalize(mean=[0.5]*3,    # 4. нормалізація каналів
                std=[0.5]*3)
])
```

> **PyTorch** → нейромережі й тензори; **torchvision** → інструменти для computer vision; **torchvision.transforms** → готові перетворення зображень.

### Допоміжна функція для відображення

> **NumPy array vs PIL Image:** `img` — це NumPy-масив (матриця чисел `height × width × 3`). `Image.fromarray(img)` перетворює його на об'єкт `PIL.Image.Image` — спеціальний тип для роботи з картинками (відкриття, зміна розміру, поворот, обрізка, збереження). Дані пікселів по суті ті самі — змінюється тип об'єкта, щоб ним було зручно працювати у бібліотеках обробки зображень. `torchvision.transforms` очікує саме PIL Image, а `matplotlib` вміє відображати обидва типи.

```python
# Створюємо допоміжну функцію для порівняння оригіналу з трансформованими зображеннями
orig_img = Image.fromarray(img)  # конвертуємо numpy-масив в PIL Image

def plot_examples(transformed_imgs: list, col_titles: list, cmap=None):
    n_cols = len(transformed_imgs) + 1           # +1 для оригінального зображення
    fig_size_x = 3 + len(transformed_imgs) * 1.5
    fig, axs = plt.subplots(1, n_cols, figsize=(fig_size_x, 2))

    axs[0].imshow(orig_img)        # перша колонка — завжди оригінал
    axs[0].set_title('original image')

    for i in range(len(transformed_imgs)):
        axs[i+1].imshow(transformed_imgs[i], cmap=cmap)
        axs[i+1].set_title(col_titles[i])

    plt.tight_layout()
    plt.show()
```

| Рядок | Що робить | Параметри |
|---|---|---|
| `Image.fromarray(img)` | Конвертує NumPy-масив у PIL Image | `img` — масив `[H, W, 3]` (uint8) |
| `plot_examples(transformed_imgs, col_titles, cmap)` | Показує оригінал + трансформовані зображення | `transformed_imgs` — список PIL Image; `col_titles` — список заголовків (має бути тієї ж довжини); `cmap` — карта кольорів (наприклад, `'gray'`) |
| `plt.subplots(1, n_cols, figsize=(...))` | Створює сітку графіків | `1` — один рядок; `n_cols` — кількість колонок; `figsize` — розмір у дюймах |

### Приклади аугментацій

#### 1. Resize

**Preprocessing (не аугментація):** основна роль Resize — привести всі зображення до одного розміру, який очікує модель. У датасеті можуть бути зображення різних розмірів (`640×480`, `1024×768`, `300×300`), а модель очікує фіксований shape, наприклад `3 × 224 × 224`. Якщо подати тензор невідповідної форми — шари мережі отримають неправильні розміри.

```
різні розміри в датасеті          після Resize
640×480  ─┐                       ┌─ 224×224
1024×768 ─┼─ T.Resize(224) ──→   ├─ 224×224
300×300  ─┘                       └─ 224×224
```

**Augmentation:** звичайний одноразовий resize лише уніфікує розмір. А от випадкові масштабні трансформації (`RandomResizedCrop`, різні zoom in/out, crop + resize) — це вже аугментація, бо модель щоразу бачить різні варіанти масштабу.

```python
# Змінюємо розмір зображення до різних розмірів (оригінал 64×64)
resized_imgs = [T.Resize(size=size)(orig_img) for size in [8, 16, 32, 128]]
plot_examples(resized_imgs, ['8x8', '16x16', '32x32', '128x128'])
```

| Параметр `T.Resize` | Тип | Що означає |
|---|---|---|
| `size` | int або tuple | Цільовий розмір. `32` → менша сторона стає 32, пропорції зберігаються. `(32, 32)` → точно 32×32 |

**Виведення:** [Resize: 32x32 та 128x128](images/aug_resize.jpg)

#### 2. Gray Scale

Перетворює кольорові зображення на відтінки сірого. Зменшує кількість каналів (3 → 1), що спрощує роботу моделі.

**Preprocessing vs Augmentation:**
- **GrayScale завжди** (до всіх зображень однаково) → **preprocessing**
- **Random GrayScale** (випадково лише до частини training images) → **augmentation**, бо модель бачить і RGB, і grayscale-версії одного об'єкта

> Grayscale не завжди зменшує канали до 1. У деяких пайплайнах grayscale-зображення представляють як 3 однакові канали, щоб shape залишався сумісним з моделлю. Також ця аугментація доречна лише якщо **колір не є критично важливою ознакою** — для класифікації дорожніх знаків видалення кольору може бути шкідливим.

```python
# Перетворюємо кольорове зображення на чорно-біле (1 канал замість 3)
gray_img = T.Grayscale()(orig_img)
plot_examples([gray_img], ["Gray"], 'gray')
```

| Параметр `T.Grayscale` | Тип | Що означає |
|---|---|---|
| `num_output_channels` | int (за замовч. 1) | Кількість каналів на виході. `1` → одноканальне зображення. `3` → три однакові канали (для сумісності з моделлю) |

**Виведення:** [Grayscale](images/aug_grayscale.jpg)

#### 3. Normalize

Нормалізація — це **preprocessing, не аугментація**. Формула для кожного пікселя:

```
normalized = (value − mean) / std
```

Приклад на зображенні `2×2` з трьома каналами:

```
R:              G:              B:
100  120         50   70        10   20
140  160         90  110        30   40

mean_R = (100+120+140+160)/4 = 130
mean_G = (50+70+90+110)/4    = 80
mean_B = (10+20+30+40)/4     = 25
```

Після віднімання mean для R-каналу:

```
100-130 = -30    120-130 = -10
140-130 =  10    160-130 =  30
```

Середнє тепер ≈ 0. Далі ділимо на `std`, щоб різні канали були в однаковому числовому масштабі — мережі легше оптимізувати ваги, коли вхідні значення не мають дуже різних розподілів.

> На практиці `mean` і `std` рахують **не для однієї картинки, а по всьому training dataset** для кожного каналу окремо. Ці самі значення потім використовують і для validation, і для test.

```python
# Нормалізуємо значення пікселів: (pixel - mean) / std для кожного каналу
normalized_img = T.Normalize(mean=(0.5, 0.5, 0.5), std=(0.5, 0.5, 0.5))(T.ToTensor()(orig_img))
normalized_img = [T.ToPILImage()(normalized_img)]  # конвертуємо назад у PIL для відображення
plot_examples(normalized_img, ["Standard normalize"])
```

| Рядок | Параметри | Що робить |
|---|---|---|
| `T.Normalize(mean, std)` | `mean=(0.5, 0.5, 0.5)` — середнє для R, G, B; `std=(0.5, 0.5, 0.5)` — стд. відхилення | Для кожного каналу: `(pixel - mean) / std`. Вхід має бути тензором (після `ToTensor`) |
| `T.ToTensor()` | — | PIL Image `[H, W, C]` → Tensor `[C, H, W]`, значення 0–255 → 0.0–1.0 |
| `T.ToPILImage()` | — | Tensor → PIL Image (зворотне перетворення для відображення) |

**Виведення:** [Normalize](images/aug_normalize.jpg)

#### 4. Random Rotation

Обертає зображення на випадковий кут — це **аугментація**, бо модель під час навчання бачить той самий об'єкт під різними кутами:

```
оригінал → повернули на -10° → повернули на +7° → повернули на +15°
```

Корисна, якщо в реальності об'єкт може бути трохи повернутим. Але не для всіх задач: сильний поворот цифр або знаків може змінити їх сенс. На практиці частіше беруть помірні кути: `±10°`, `±15°`, `±20°`.

```python
# Обертаємо зображення на випадковий кут (до 50°, 100°, 150°)
rotated_imgs = [T.RandomRotation(degrees=d)(orig_img) for d in range(50, 151, 50)]
plot_examples(rotated_imgs, ["Rotation 50", "Rotation 100", "Rotation 150"])
```

| Параметр `T.RandomRotation` | Тип | Що означає |
|---|---|---|
| `degrees` | int або tuple | Діапазон кутів обертання. `50` → від −50° до +50°. `(30, 60)` → від 30° до 60° |

> **Чому зображення виглядає розмитим / з чорними кутами?** При повороті пікселі більше не лягають точно на сітку — бібліотека обчислює нові значення через **інтерполяцію**, що може давати розмиття та "сходинки". Чорні кути — це ділянки, де після повороту немає даних з оригіналу (fill value = 0). Ефект особливо помітний на маленьких зображеннях (`64×64`) з великими кутами (50°–150°).

**Виведення:** [Random Rotation](images/aug_rotation.jpg)

#### 5. Center Crop

Вирізає центральну частину зображення — краї відкидаються:

```
┌──────────────┐
│              │
│   ┌──────┐   │
│   │ crop │   │
│   └──────┘   │
│              │
└──────────────┘
```

**CenterCrop — це preprocessing, а не augmentation**, бо він завжди вирізає одну й ту саму центральну область. Корисний лише якщо основний об'єкт зазвичай знаходиться в центрі — якщо він збоку, CenterCrop може його обрізати.

Для augmentation використовують `T.RandomCrop(...)`, де кожного разу вирізається інша область.

```python
# Вирізаємо квадрат із центру зображення різних розмірів (оригінал 64×64)
center_crops = [T.CenterCrop(size=size)(orig_img) for size in (48, 32, 16)]
plot_examples(center_crops, ['48x48', '32x32', '16x16'])
```

| Параметр `T.CenterCrop` | Тип | Що означає |
|---|---|---|
| `size` | int або tuple | Розмір вирізки з центру. `640` → квадрат 640×640. `(640, 480)` → прямокутник |

**Виведення:** [Center Crop](images/aug_center_crop.jpg)

#### 6. Random Crop

Вирізає **випадкову** частину зображення — це **augmentation**, бо кожного разу вирізається інша область. З одного фото модель бачить різні варіанти:

```
CenterCrop → завжди вирізає центр (preprocessing)
RandomCrop → кожного разу випадкове місце (augmentation)

RandomCrop #1: [ пальці + частина долоні ]
RandomCrop #2: [ долоня + зап'ястя      ]
RandomCrop #3: [ майже вся рука, трохи обрізана ]
```

Модель вчиться: *«Об'єкт не обов'язково має бути ідеально по центру і повністю видимим».*

> Важливо не переборщити: якщо crop занадто маленький, можна випадково вирізати майже весь об'єкт, і label вже буде сумнівним.

```python
# Вирізаємо випадкову ділянку зображення різних розмірів (оригінал 64×64)
random_crops = [T.RandomCrop(size=size)(orig_img) for size in (48, 32, 16)]
plot_examples(random_crops, ['48x48', '32x32', '16x16'])
```

| Параметр `T.RandomCrop` | Тип | Що означає |
|---|---|---|
| `size` | int або tuple | Розмір випадкової вирізки. `48` → квадрат 48×48 з випадкової позиції |

**Виведення:** [Random Crop](images/aug_random_crop.jpg)

#### 7. Gaussian Blur

Гаусове розмиття — може бути **augmentation**, якщо застосовувати випадково до частини training images.

**Як працює:** ядро (наприклад `3×3`) проходить по зображенню і замінює кожен піксель на **зважене середнє** його сусідів. Центральні сусіди мають більшу вагу, далекі — меншу:

[Як працює гаусівське розмиття (Gaussian Blur)](images/gaussian_blur_explained.png)

> **Виправлення до схеми:** правильний результат обчислення для центрального пікселя — **137.5 ≈ 138**, а не 131. Перевірка: 0.0625×100 + 0.125×120 + 0.0625×100 + 0.125×130 + 0.25×200 + 0.125×130 + 0.0625×100 + 0.125×120 + 0.0625×100 = 27.5 + 82.5 + 27.5 = **137.5**.

**Навіщо давати моделі розмиті зображення?** Без blur модель може надто покладатися на дрібні випадкові деталі: шум камери, тонкі контури, текстуру конкретного фото. Якщо частина training images трохи розмита, модель змушена спиратися на **стійкіші ознаки**: загальну форму, великі контури, структуру об'єкта. Але сильне розмиття вже шкідливе — воно знищить справді корисні деталі.

> **Gaussian Blur kernel vs CNN kernel:** ядро Gaussian Blur має ваги, визначені **формулою Гауса наперед** — вони не навчаються. А ядро Conv2D починає з випадкових ваг і **навчається** через backpropagation шукати корисні патерни.

```python
# Застосовуємо розмиття Гауса з різною інтенсивністю (sigma)
# kernel_size має бути непарним і не більшим за розмір зображення
blurred_imgs = [T.GaussianBlur(kernel_size=(5, 5), sigma=sigma)(orig_img) for sigma in (1, 3, 7)]
plot_examples(blurred_imgs, ['sigma=1', 'sigma=3', 'sigma=7'])
```

| Параметр `T.GaussianBlur` | Тип | Що означає |
|---|---|---|
| `kernel_size` | int або tuple | Розмір ядра розмиття (має бути непарним). `(5, 5)` → квадратне ядро 5×5 |
| `sigma` | float або tuple | Стандартне відхилення Гауса — інтенсивність розмиття. Більше `sigma` → сильніше розмиття |

**Виведення:** [Gaussian Blur](images/aug_gaussian_blur.jpg)

#### 8. Gaussian Noise

Додає випадковий шум із розподілу Гауса. Змушує модель вивчати найважливішу інформацію, ігноруючи шум.

```python
# Функція для додавання випадкового шуму Гауса до зображення
def add_noise(inputs, noise_factor=0.3):
    noisy = inputs + torch.randn_like(inputs) * noise_factor  # додаємо випадковий шум
    noisy = torch.clip(noisy, 0., 1.)  # обмежуємо значення діапазоном [0, 1]
    return noisy

# Генеруємо зашумлені версії з різною інтенсивністю шуму
noise_imgs = [add_noise(T.ToTensor()(orig_img), noise_factor) for noise_factor in (0.3, 0.6, 0.9)]
noise_imgs = [T.ToPILImage()(noise_img) for noise_img in noise_imgs]
plot_examples(noise_imgs, ["noise_factor=0.3", "noise_factor=0.6", "noise_factor=0.9"])
```

| Рядок | Що робить | Параметри |
|---|---|---|
| `add_noise(inputs, noise_factor)` | Додає випадковий шум до тензора | `inputs` — тензор зображення [C, H, W]; `noise_factor` — інтенсивність шуму (0.3 = слабкий, 0.9 = сильний) |
| `torch.randn_like(inputs)` | Генерує тензор випадкових чисел тієї ж форми | Нормальний розподіл (mean=0, std=1) |
| `torch.clip(noisy, 0., 1.)` | Обмежує значення діапазоном [0, 1] | Щоб значення пікселів не вийшли за допустимі межі |

**Виведення:** [Gaussian Noise](images/aug_gaussian_noise.jpg)

#### 9. Random Blocks

Це **augmentation**: на зображенні випадково закриваються квадратні ділянки чорним кольором. Модель усе одно повинна правильно визначити клас.

**Навіщо?** Щоб модель не покладалась на одну конкретну маленьку ознаку. Наприклад, якщо для класу `5` вона завжди дивиться лише на кінчики пальців, а ми частину закриємо — їй доведеться використовувати й інші ознаки: форму долоні, положення інших пальців, загальний контур.

```text
Random Blocks → частину інформації навмисно приховали
              → модель змушена використовувати інші ознаки
              → краща стійкість до частково закритих об'єктів
```

Це схоже на техніки **Random Erasing / Cutout**. Під час навчання те саме зображення щоразу виглядає трохи інакше, що збільшує різноманітність training data. Але важливо не переборщити: якщо закрити занадто багато, модель отримає майже нерозпізнавану картинку.

```python
# Функція для накладання чорних квадратів на випадкові місця зображення
def add_random_boxes(img, n_k, size=32):
    h, w = size, size
    img = np.array(img)                # PIL → numpy масив (array, не asarray — щоб можна було змінювати)
    img_size = img.shape[1]
    boxes = []
    for k in range(n_k):
        y, x = np.random.randint(0, img_size - w, (2,))  # випадкова позиція
        img[y:y+h, x:x+w] = 0         # заповнюємо чорним (0)
        boxes.append((x, y, h, w))
    img = Image.fromarray(img.astype('uint8'), 'RGB')
    return img

# Накладаємо чорні квадрати розміром 8×8 та 16×16 (оригінал 64×64)
blocks_imgs = [add_random_boxes(orig_img, n_k=5, size=8), add_random_boxes(orig_img, n_k=5, size=16), add_random_boxes(orig_img, n_k=10, size=8)]
plot_examples(blocks_imgs, ["5 boxes 8x8", "5 boxes 16x16", "10 boxes 8x8"])
```

| Параметр `add_random_boxes` | Тип | Що означає |
|---|---|---|
| `img` | PIL Image | Вхідне зображення |
| `n_k` | int | Кількість чорних квадратів для накладання |
| `size` | int (за замовч. 32) | Розмір сторони квадрата в пікселях |

| Рядок | Що робить |
|---|---|
| `np.array(img)` | PIL Image → NumPy-масив (копія, яку можна змінювати; `np.asarray` дає read-only) |
| `np.random.randint(0, img_size - w, (2,))` | Генерує 2 випадкові координати (y, x) для позиції квадрата |
| `img[y:y+h, x:x+w] = 0` | Заповнює ділянку нулями (чорний колір) |
| `Image.fromarray(img.astype('uint8'), 'RGB')` | NumPy-масив → PIL Image; `'RGB'` — режим кольору |

**Виведення:** [Random Blocks](images/aug_random_blocks.jpg)

До цього ми лише **дивилися на дані й окремі трансформації**. Тепер готуємо все до реального навчання моделі — створюємо **input pipeline**:

```text
папка з jpg → Dataset → DataLoader → batches → model → training
```

### Крок 4. Клас Dataset

**Що це:** PyTorch-обгортка, яка описує, як отримувати окремі зразки з нашого набору даних.

Замість того, щоб вручну для кожного фото відкривати файл, визначати label, застосовувати resize/flip/tensor — ми один раз описуємо правила в `Dataset`, а PyTorch робить це автоматично:

```text
для кожного idx:
    знайти файл → взяти label з назви → відкрити PIL Image
    → застосувати transform → повернути (image_tensor, label)
```

Наприклад: `train_dataset[0]` → `(Tensor [3, 64, 64], 2)`

**Що потрібно реалізувати:**

| Метод | Що повертає | Коли викликається |
|---|---|---|
| `__init__()` | — | При створенні об'єкта: зберігає шляхи, мітки, трансформації |
| `__len__()` | Кількість зразків | `len(dataset)` → 1080 |
| `__getitem__(idx)` | i-й зразок та мітку | `dataset[42]` → (tensor_image, label) |

```python
# Створюємо клас Dataset для завантаження зображень знаків
class SIGNSDataset(Dataset):
    def __init__(self, data_dir, transform):
        self.filenames = os.listdir(data_dir)
        self.filenames = [os.path.join(data_dir, f) for f in self.filenames if f.endswith('.jpg')]
        self.labels = [int(filename.split('/')[-1][0]) for filename in self.filenames]  # "0_IMG.jpg" → 0
        self.transform = transform

    def __len__(self):
        return len(self.filenames)  # кількість зображень у наборі

    def __getitem__(self, idx):
        image = Image.open(self.filenames[idx])  # відкриваємо зображення через PIL
        image = self.transform(image)             # застосовуємо трансформації
        return image, self.labels[idx]            # повертаємо (тензор, мітка)
```

**Пояснення рядок за рядком:**

| Рядок | Що робить | Навіщо |
|---|---|---|
| `class SIGNSDataset(Dataset):` | Наслідуємо від PyTorch `Dataset` | DataLoader вимагає об'єкт Dataset з `__len__` та `__getitem__` |
| `os.listdir(data_dir)` | Список усіх файлів у директорії | Збираємо шляхи до зображень |
| `f.endswith('.jpg')` | Фільтруємо тільки JPG | Ігноруємо сторонні файли |
| `filename.split('/')[-1][0]` | Беремо перший символ імені файлу | Ім'я файлу починається з класу: `0_IMG_5864.jpg` → клас `0` |
| `self.transform = transform` | Зберігаємо трансформації | Будуть застосовані до кожного зображення при зверненні |
| `Image.open(self.filenames[idx])` | Відкриваємо зображення через PIL | PIL Image сумісний з torchvision.transforms |
| `self.transform(image)` | Застосовуємо трансформації (resize, flip, to_tensor) | Перетворюємо PIL Image → тензор з аугментаціями |

train_transformer = T.Compose([

**Пояснення:**

| Трансформація | Що робить | Навіщо |
|---|---|---|
| `T.Compose([...])` | Об'єднує кілька трансформацій у послідовний пайплайн | Всі трансформації застосовуються одна за одною |
| `T.Resize(64)` | Змінює розмір до 64×64 | Уніфікація розмірів — мережа очікує фіксований розмір входу |
| `T.RandomHorizontalFlip()` | З імовірністю 50% дзеркально відображає зображення | Аугментація — збільшує різноманітність даних |
| `T.ToTensor()` | PIL Image `[H, W, C]` → Tensor `[C, H, W]`, значення 0–255 → 0.0–1.0 | PyTorch працює з тензорами, а не з PIL Image |

> **Навіщо два трансформери?** `train_transformer` містить аугментацію (`RandomHorizontalFlip`) — урізноманітнює дані під час навчання. `eval_transformer` — без аугментації, бо test має показати, наскільки добре модель працює на **реальних незмінених даних**.

### Крок 7. Клас моделі (BaselineModel)

**Клас моделі** — Python-клас, у якому описується **архітектура нейронної мережі**: які шари вона має і в якому порядку через них проходять дані.

```python
class BaselineModel(nn.Module):  # успадковується від базового класу PyTorch
```

Усередині дві головні частини:
- `__init__()` — описує **які шари існують** (список "деталей")
- `forward()` — описує **як дані проходять через ці шари** (порядок обробки)

```text
class BaselineModel = креслення будинку
model = BaselineModel() = конкретний будинок з власними вагами
```

**Що будуємо:** згорткову нейронну мережу з трьома згортковими шарами (base) і двома повнозв'язними шарами (head).

```python
class BaselineModel(nn.Module):

    def __init__(self):
        super().__init__()
        self.num_channels = 32

        # Згорткова основа (convolution base) — витягує ознаки
        self.conv1 = nn.Conv2d(3, self.num_channels, 3, stride=1, padding=1)
        self.conv2 = nn.Conv2d(self.num_channels, self.num_channels*2, 3, stride=1, padding=1)
        self.conv3 = nn.Conv2d(self.num_channels*2, self.num_channels*4, 3, stride=1, padding=1)

        # Класифікаційні шари (head) — передбачає клас
        self.fc1 = nn.Linear(8*8*self.num_channels*4, self.num_channels*4)
        self.fc2 = nn.Linear(self.num_channels*4, 6)

    def forward(self, s):
        #                                          -> batch_size x 3 x 64 x 64
        s = self.conv1(s)                          # batch_size x 32 x 64 x 64
        s = F.relu(F.max_pool2d(s, 2))             # batch_size x 32 x 32 x 32
        s = self.conv2(s)                          # batch_size x 64 x 32 x 32
        s = F.relu(F.max_pool2d(s, 2))             # batch_size x 64 x 16 x 16
        s = self.conv3(s)                          # batch_size x 128 x 16 x 16
        s = F.relu(F.max_pool2d(s, 2))             # batch_size x 128 x 8 x 8

        # вирівнюємо вихід для кожного зображення
        s = s.view(-1, 8*8*self.num_channels*4)    # batch_size x 8192

        # повнозв'язні шари
        s = F.relu(self.fc1(s))                    # batch_size x 128
        s = self.fc2(s)                            # batch_size x 6

        return F.log_softmax(s, dim=1)
```

**Покроковий розбір архітектури:**

| Шар | Операція | Вхід → Вихід | Що відбувається |
|---|---|---|---|
| **Вхід** | — | `[N, 3, 64, 64]` | RGB-зображення 64×64 |
| **conv1** | Conv2d(3→32, 3×3, pad=1) | `[N, 3, 64, 64]` → `[N, 32, 64, 64]` | 32 фільтри шукають прості ознаки (краї, кути) |
| **pool1** | MaxPool2d(2) + ReLU | `[N, 32, 64, 64]` → `[N, 32, 32, 32]` | Зменшує розмір вдвічі, зберігає максимуми |
| **conv2** | Conv2d(32→64, 3×3, pad=1) | `[N, 32, 32, 32]` → `[N, 64, 32, 32]` | 64 фільтри шукають складніші ознаки (текстури) |
| **pool2** | MaxPool2d(2) + ReLU | `[N, 64, 32, 32]` → `[N, 64, 16, 16]` | Ще зменшення |
| **conv3** | Conv2d(64→128, 3×3, pad=1) | `[N, 64, 16, 16]` → `[N, 128, 16, 16]` | 128 фільтрів — найскладніші ознаки (форми) |
| **pool3** | MaxPool2d(2) + ReLU | `[N, 128, 16, 16]` → `[N, 128, 8, 8]` | Фінальне зменшення |
| **flatten** | view(-1, 8192) | `[N, 128, 8, 8]` → `[N, 8192]` | 3D-тензор → 1D-вектор для повнозв'язного шару |
| **fc1** | Linear(8192→128) + ReLU | `[N, 8192]` → `[N, 128]` | Стиснення ознак |
| **fc2** | Linear(128→6) | `[N, 128]` → `[N, 6]` | 6 виходів — по одному на кожен клас |
| **log_softmax** | LogSoftmax(dim=1) | `[N, 6]` → `[N, 6]` | Перетворює в лог-ймовірності |

**Що таке Max Pooling?**

Max Pooling бере **максимальне значення** у вікні заданого розміру і записує його у вихід. Це зменшує розмірність і зберігає найважливіші ознаки.

```
Вікно 2×2:

⎡ 1  3 ⎤
⎣ 2  4 ⎦  →  max = 4
```

> **Навіщо `F.log_softmax`, а не `F.softmax`?** `log_softmax` = log(softmax(x)). Він числово стабільніший, бо уникає проблем із дуже малими числами після softmax. Використовується разом з `nn.CrossEntropyLoss` (яка внутрішньо вже містить softmax, або з `nn.NLLLoss`, яка очікує log-ймовірності).

### Крок 11. Оптимізатор — Adam

```python

```

| Параметр `torch.optim.Adam` | Значення | Що означає |
|---|---|---|
| `model.parameters()` | ітератор ваг | Усі параметри моделі, які потрібно оптимізувати |
| `lr` | `1e-3` (= 0.001) | Learning rate — розмір кроку оновлення ваг. Для Adam типовий lr = 0.001 |

#### SGD vs Adam — ключові відмінності

- **SGD** = **S**tochastic **G**radient **D**escent (стохастичний градієнтний спуск)
- **Adam** = **Ada**ptive **M**oment Estimation (адаптивна оцінка моментів)

| Аспект | SGD | Adam |
|---|---|---|
| **Оновлення ваг** | `W(t+1) = W(t) − α · ∇J(W(t))` | Адаптивна швидкість для кожного параметра |
| **Швидкість навчання** | Одна для всіх параметрів, потрібно підбирати | Автоматично адаптується для кожного параметра |
| **Стійкість до шуму** | Чутливий до шуму в градієнтах | Стійкий завдяки експоненціальному згладжуванню |
| **Збіжність** | Може повільно збігатися | Зазвичай швидша збіжність |
| **Типовий lr** | 0.01 | 0.001 (1e-3) |

> **Збіжність (convergence)** — loss поступово наближається до мінімуму, зміни стають меншими: `1.2 → 0.9 → 0.7 → 0.55 → 0.48 → 0.46`. **Розбіжність (divergence)** — навпаки, loss зростає: `1.2 → 0.8 → 1.5 → 2.4 → 7.8`. Аналогія: convergence — крок за кроком спускаєшся в долину; divergence — занадто великі кроки і віддаляєшся від дна.

---

#### SGD — найпростіша логіка

Формула:

```
W(t+1) = W(t) − α · ∇J(W(t))
```

Розшифруємо:

- `W` = **weights, ваги моделі** (наприклад, `Wₜ = 5`)
- `t` = поточний крок навчання (`Wₜ` = вага зараз, `Wₜ₊₁` = вага після оновлення)
- `J` = **loss function** — наскільки поганий прогноз (малий J → добре, великий J → погано)
- `∇J(Wₜ)` = **градієнт loss відносно ваг** — "у який бік і наскільки треба змінити вагу?"
- `α` (alpha) = **learning rate** — розмір кроку

Приклад:

```text
W = 5, gradient = 2, α = 0.1

нова вага = 5 − 0.1 × 2 = 4.8
```

**Чому мінус?** Градієнт показує напрямок **зростання** loss. А ми хочемо loss **зменшити**. Тому йдемо в протилежний бік — звідси **gradient descent** (градієнтний спуск).

#### Аналогія SGD: спуск з гори в тумані

Ти стоїш на горі в густому тумані. Не бачиш усієї гори, але відчуваєш: "у який бік схил іде вниз" — це **gradient**.

`learning rate` визначає довжину кроку:

```text
lr маленький → . . . . . . . . → безпечно, але довго
lr великий   → ← → ← → ← →    → перестрибуєш через дно (divergence!)
```

---

#### Як працює Adam

Adam теж хоче зменшити loss, але має **пам'ять**:

```text
SGD:  "Дивлюся на поточний gradient → роблю крок"
Adam: "Дивлюся на gradient + пам'ятаю попередні кроки + оцінюю стабільність"
```

Adam поєднує переваги **AdaGrad** (адаптивне масштабування) та **RMSProp** (згладжування середнього квадрата градієнтів).

---

**Перший момент (m) — середній напрямок:**

```
m(t) = β₁ · m(t−1) + (1 − β₁) · g(t)
```

`g(t)` — поточний gradient. `m(t)` — приблизно **середній напрямок gradients останнім часом**.

`β₁ = 0.9` означає: 90% попередньої інформації + 10% нового gradient.

Приклад:

```text
старе m = 2, новий gradient = 4, β₁ = 0.9

m = 0.9 × 2 + 0.1 × 4 = 1.8 + 0.4 = 2.2
```

Один раптовий gradient `4` не змусив Adam різко змінити напрямок.

---

**Другий момент (v) — розмір gradients:**

```
v(t) = β₂ · v(t−1) + (1 − β₂) · g(t)²
```

Тут Adam дивиться на **розмір** gradients (квадрат прибирає знак: `(-4)² = 16` і `(+4)² = 16`).

`β₂ = 0.999` — Adam дуже плавно накопичує цю статистику.

```text
m → куди ми переважно рухаємося?
v → наскільки нестабільні / великі gradients?
```

---

**Корекція зміщення (bias correction):**

На початку `m = 0` і `v = 0` — Adam ще нічого не знає. Тому перші оцінки штучно занадто близькі до нуля. Корекція це виправляє:

```
m̂(t) = m(t) / (1 − β₁ᵗ)
v̂(t) = v(t) / (1 − β₂ᵗ)
```

Шапочка `^` означає **скоригована оцінка**.

---

**Фінальне оновлення параметрів:**

```
             α · m̂(t)
W(t+1) = W(t) − ─────────────
              √v̂(t) + ε
```

По-людськи: **нова вага = стара вага − розумно підібраний крок**, де:

- `α` — базова швидкість навчання
- `m̂` — куди gradients переважно ведуть
- `v̂` — наскільки великими/мінливими вони були
- `ε ≈ 10⁻⁸` — щоб не ділити на нуль

---

#### Аналогія SGD vs Adam: керування автомобілем

**SGD** дивиться тільки на те, що відбувається **прямо зараз**:

```text
"Дорога повертає ліворуч → повертаю ліворуч"
"Тепер праворуч → повертаю праворуч"
Результат: ← → ← → ← → (смикається)
```

**Adam** пам'ятає контекст:

```text
"Зараз дорога трохи повернула праворуч, але останні 20 секунд
 ми загалом рухалися ліворуч. Не буду різко крутити кермо."

"На цій ділянці напрямок постійно скаче — тут краще їхати обережніше."
```

---

#### Головна різниця

У SGD — один `learning rate` для всіх параметрів. Adam має базовий lr, **але додатково масштабує оновлення кожного параметра залежно від його історії gradients**. Одна вага може отримати маленький крок, інша — більший.

**SGD:** «Подивився на поточний схил → зробив крок».
**Adam:** «Подивився на схил + згадав попередні кроки + оцінив стабільність → підібрав крок».

| Перевага Adam | Пояснення |
|---|---|
| **Адаптивність** | Кожен параметр має свою швидкість навчання |
| **Стійкість до шуму** | Експоненціальне згладжування згладжує шум у градієнтах |
| **Корекція зміщення** | На початку навчання моменти зміщені до нуля — Adam це виправляє |

# Ініціалізуємо списки для збереження метрик по епохах

### Крок 13. Цикл тренування

```python
# Навчаємо модель із відстеженням loss та accuracy на train і test
for epoch in tqdm(range(num_epochs)):

    # ═══════════════ ТРЕНУВАННЯ ═══════════════
    model.train()  # вмикаємо режим навчання

    train_epoch_loss = []
    train_epoch_acc = []

    for i, (train_batch, labels_batch) in tqdm(enumerate(train_dataloader)):
        if cuda:  # переносимо дані на GPU
            train_batch = train_batch.cuda(non_blocking=True)
            labels_batch = labels_batch.cuda(non_blocking=True)

        output_batch = model(train_batch)              # forward pass — прогноз моделі
        loss = criterion(output_batch, labels_batch)   # обчислюємо функцію втрат

        optimizer.zero_grad()  # обнуляємо градієнти попереднього кроку
        loss.backward()        # backpropagation — обчислюємо градієнти
        optimizer.step()       # оновлюємо ваги моделі

        # зберігаємо метрики батчу (переносимо з GPU на CPU для numpy)
        batch_loss = loss.cpu().detach().numpy()
        batch_acc = balanced_accuracy_score(
            np.argmax(output_batch.cpu().detach().numpy(), axis=1),  # прогнозований клас
            labels_batch.cpu().detach().numpy()                       # справжній клас
        )

        train_epoch_loss.append(batch_loss)
        train_epoch_acc.append(batch_acc)

    print(f'Train epoch [{epoch+1}/{num_epochs}], '
          f'Loss: {np.mean(train_epoch_loss):.4f}, Acc: {np.mean(train_epoch_acc)}')
    train_accs.append(np.mean(train_epoch_acc))
    train_losses.append(np.mean(train_epoch_loss))

    # ═══════════════ ТЕСТУВАННЯ ═══════════════
    model.eval()  # вмикаємо режим оцінки (вимикає Dropout, BatchNorm)

    test_epoch_loss = []
    test_epoch_acc = []

    with torch.no_grad():  # вимикаємо обчислення градієнтів — економимо пам'ять
        for i, (test_batch, labels_batch) in enumerate(test_dataloader):
            if cuda:
                test_batch = test_batch.cuda(non_blocking=True)
                labels_batch = labels_batch.cuda(non_blocking=True)

            output_batch = model(test_batch)
            loss = criterion(output_batch, labels_batch)

            batch_loss = loss.cpu().detach().numpy()
            batch_acc = balanced_accuracy_score(
                np.argmax(output_batch.cpu().detach().numpy(), axis=1),
                labels_batch.cpu().detach().numpy()
            )

            test_epoch_loss.append(batch_loss)
            test_epoch_acc.append(batch_acc)

    print(f'Test epoch [{epoch+1}/{num_epochs}], '
          f'Loss: {np.mean(test_epoch_loss):.4f}, Acc: {np.mean(test_epoch_acc)}')
    test_accs.append(np.mean(test_epoch_acc))
    test_losses.append(np.mean(test_epoch_loss))
```

**Пояснення ключових рядків:**

| Рядок | Що робить | Навіщо |
|---|---|---|
| `model.train()` | Вмикає режим навчання | Активує Dropout, BatchNorm (якщо є) |
| `.cuda(non_blocking=True)` | Переносить дані на GPU | `non_blocking=True` — асинхронна передача для швидкості |
| `output_batch = model(train_batch)` | Forward pass — прогноз моделі | Пропускає батч зображень через мережу |
| `criterion(output_batch, labels_batch)` | Обчислює Cross-Entropy Loss | Вимірює, наскільки прогноз відрізняється від правильних міток |
| `optimizer.zero_grad()` | Обнуляє градієнти | PyTorch **додає** градієнти — без обнуління вони накопичуються |
| `loss.backward()` | Backpropagation | Обчислює градієнти всіх параметрів |
| `optimizer.step()` | Оновлює ваги | W = W − lr × gradient (з адаптацією Adam) |
| `.cpu().detach().numpy()` | GPU → CPU, від'єднати від графу, tensor → numpy | Для збереження метрик у звичайних Python-списках |
| `np.argmax(..., axis=1)` | Індекс максимального значення по класах | Перетворює ймовірності [0.1, 0.8, 0.05, ...] → клас 1 |
| `balanced_accuracy_score(...)` | Збалансована точність | Враховує дисбаланс класів (хоча у нас вони збалансовані) |
| `model.eval()` | Вмикає режим оцінки | Деактивує Dropout, BatchNorm використовує збережені статистики |
| `torch.no_grad()` | Вимикає обчислення градієнтів | Економія пам'яті — на тесті градієнти не потрібні |

**Ключові відмінності train vs eval:**

| Аспект | Train | Eval |
|---|---|---|
| `model.train()` / `model.eval()` | Активує Dropout, BatchNorm | Деактивує |
| `torch.no_grad()` | Не використовується | Вимикає автоградієнт → менше пам'яті |
| `optimizer.step()` | Оновлює ваги | **Не робимо!** Тестові дані не впливають на модель |
| `loss.backward()` | Обчислює градієнти | **Не робимо!** |

**Виведення:** [Графіки тренування: Loss та Accuracy](images/training_graphs.jpg)

**Що бачимо на графіках:**
- **Loss рівномірно спадає** — модель ефективно мінімізує помилки
- **Accuracy зростає** до ≈ 90% — модель робить все точніші передбачення
- Train та Validation **близькі** — немає значного overfitting

**Як розпізнати проблеми:**

| Ситуація | Що на графіку | Що робити |
|---|---|---|
| **Нормально** | Train ≈ Validation, loss ↓, accuracy ↑ | Все ОК! |
| **Overfitting** | Train loss ↓, Validation loss ↑ | Більше аугментацій, Dropout, менша мережа |
| **Underfitting** | Обидва loss високі, accuracy низька | Більше шарів/нейронів, більше епох, менший lr |

**Висновки:**
- Після завершення навчання спостерігається значне зниження функції втрат
- Точність на тестовій вибірці зросла — модель успішно зійшлася
- Модель може бути використана для подальших завдань

### Класифікація зображень з CNN

```
1. Встановити бібліотеки         → pip install opencv-python pillow torchvision
2. Завантажити/переглянути дані  → os.listdir, cv2.imread, plt.imshow
3. Зрозуміти зображення          → Матриці: Grayscale [H,W], RGB [3,H,W]
4. Визначити трансформації        → T.Compose([T.Resize, T.RandomHorizontalFlip, T.ToTensor])
5. Створити Dataset              → __init__, __len__, __getitem__
6. Створити DataLoader            → batch_size, shuffle, num_workers
7. Визначити модель (CNN)         → Conv2d → ReLU → MaxPool2d → ... → Linear → log_softmax
8. Визначити loss + optimizer     → CrossEntropyLoss + Adam
9. Тренувальний цикл (батчі)     → for batch in dataloader: forward → loss → backward → step
10. Тестування (батчі)            → model.eval() + torch.no_grad()
11. Аналіз графіків               → loss ↓, accuracy ↑
```

### Ключові відмінності від теми 4

| **Аугментація** | Не застосовується | Обов'язкова (Flip, Rotation, Crop...) |
