### 1.2 Метрики Average Precision і Mean Average Precision

Перш ніж аналізувати графіки, потрібно зрозуміти метрику **mAP**, яка є головним показником якості детектора.

#### Average Precision (AP)

**Average Precision** — площа під кривою Precision-Recall (PR-кривою) для одного класу.

**Як будується PR-крива:**

1. Сортуємо всі передбачення (для одного класу) за спаданням confidence score
2. Послідовно «включаємо» кожне передбачення в множину результатів
3. На кожному кроці обчислюємо поточні Precision і Recall:
   - `Precision = TP / (TP + FP)` — з усіх наших знахідок, яка частка правильна
   - `Recall = TP / (TP + FN)` — з усіх реальних об'єктів, яку частку ми знайшли
4. Малюємо криву: вісь X — Recall (від 0 до 1), вісь Y — Precision (від 0 до 1)

```
Precision
  1 |*..               ← При низькому Recall (суворий поріг) Precision висока
    |   *..
0.5 |       *..
    |           *..
  0 |_______________
    0   0.5   1   Recall
```

**AP** = площа під цією кривою (обчислюється методом трапецій або в 101 точці по Recall).

> **Інтерпретація:** AP від 0 до 1. AP = 1.0 — ідеальна детекція для цього класу при будь-якому порозі. Чим більше і «заповнена» крива — тим вищий AP.

#### Mean Average Precision (mAP)

Коли в датасеті є **N класів**, обчислюємо AP для кожного класу окремо, а потім усереднюємо:

$$\text{mAP} = \frac{1}{N} \sum_{i=1}^{N} AP_i$$

де `N` — кількість класів, `APᵢ` — Average Precision для i-го класу.

**Два варіанти mAP у YOLO:**

| Метрика | Що означає | Характеристика |
| ------- | ---------- | -------------- |
| `mAP@0.5` | AP при IoU threshold = 0.5 | «Легкий» варіант: достатньо 50% перекриття |
| `mAP@0.50:0.95` | AP усереднений по IoU 0.50–0.95 з кроком 0.05 | Суворий COCO-критерій (11 значень IoU) |

> **Увага:** `mAP@0.5` означає, що детекція вважається правильною (TP), якщо IoU між передбаченою і реальною рамкою ≥ 0.5. Це **не** єдиний правильний поріг — просто один із поширених evaluation protocols. Детальніше про вибір порогу IoU — у темі 7.

#### Поля у виводі YOLO val

YOLO виводить таку таблицю після тренування/валідації:

| Поле | Що означає |
| ---- | ---------- |
| `Class` | Назва класу |
| `Images` | Кількість зображень у val, де є цей клас |
| `Instances` | Кількість анотованих об'єктів цього класу у val |
| `P` (Precision) | Частка правильних детекцій з усіх виявлених (при оптимальному threshold) |
| `R` (Recall) | Частка знайдених реальних об'єктів з усіх реальних |
| `mAP50` | mAP при IoU = 0.5 |
| `mAP50-95` | mAP при IoU 0.50:0.95 |

### 1.3 Розбір кожного графіка

#### F1-Confidence Curve

![F1-Confidence Curve: всі 10 класів + загальна синя лінія](images/f1_curve.png)

*Крива F1-міри від порогу впевненості. Синя жирна лінія — усі класи. Максимум: F1 = 0.87 при conf = 0.457.*

**Що на осях:**
- Вісь X: `Confidence threshold` — мінімальна впевненість, яку модель має мати, щоб «повідомити» про об'єкт. Нижче порогу — детекція відкидається.
- Вісь Y: `F1-score` = `2 · Precision · Recall / (Precision + Recall)` — гармонічне середнє між Precision і Recall.

**Як читати:**
- Ліворуч (conf → 0): порог дуже низький → модель «повідомляє» про всі можливі рамки → Recall = 1, але Precision низька → F1 нижня.
- Праворуч (conf → 1): порог дуже високий → модель повідомляє лише про «найвпевненіші» рамки → Precision = 1, але Recall низька → F1 нижня.
- **Оптимум** — там де F1 максимальний. Для нашої моделі: `F1 = 0.87` при `conf = 0.457`.

**Висновок:** якщо встановити `conf=0.457` при inference, модель матиме F1 ≈ 87% по всіх класах — хороший баланс між «не пропустити об'єкт» і «не вигадати зайвого».

**Що робити якщо погано:** якщо F1 < 0.5 або пік дуже вузький — модель потребує більше даних, більше епох або кращої аугментації.

**Як читати:**
- Зростання вправо: чим вищий поріг впевненості → тим «чистіші» залишаються детекції → Precision наближається до 1.
- **all classes 1.00 at 0.939**: при conf = 0.939 модель повідомляє лише про ті об'єкти, у яких вона дуже впевнена, і всі вони правильні.

> **Нюанс:** висока Precision при conf = 0.939 — це не обов'язково добре, бо Recall при цьому буде дуже низький (модель пропускає більшість об'єктів). Дивись наступний графік.

![Recall-Confidence Curve: Recall від confidence threshold](images/r_curve.png)

*Recall від порогу впевненості. Загальна лінія: Recall = 0.89 при conf = 0.000.*

- Вісь X: `Confidence threshold`.
- Вісь Y: `Recall`.

**Як читати:**
- Спадання вправо: чим вищий поріг → тим більше детекцій відкидаємо → Recall падає.
- При conf = 0: приймаємо абсолютно всі детекції → максимальний Recall ≈ 0.89 (11% реальних об'єктів модель не знаходить взагалі).

**Зв'язок Precision і Recall:**

```
Низький conf →  Recall = MAX,    Precision = LOW
Оптимальний → Recall та Precision збалансовані (саме тут F1 максимальний)
Високий conf → Recall = LOW,    Precision = MAX
```

## ЧАСТИНА 2. АВТОКОДЕРИ: ТЕОРІЯ

### 2.1 Що таке автокодер?

**Autoencoder (автокодер)** — це архітектура глибокого навчання, яка **стискає вхідні дані** у компактне представлення і **відновлює** їх назад.

На відміну від більшості нейромереж, автокодер:
- Навчається **без міток** (unsupervised learning)
- **Вхід = Вихід** — мета не класифікація, а якомога точніше відновлення вхідних даних
- «Корисний ефект»: по дорозі крізь вузьке місце (latent space) мережа вивчає компактне представлення даних

#### Схема архітектури

![Autoencoder: Input → Encoder → Code → Decoder → Output](images/autoencoder_architecture.png)

*Автокодер: вхідний шар → Encoder (зменшення розмірності) → Code / Latent Space → Decoder (збільшення розмірності) → вихідний шар.*

```
Вхід (велика розмірність)   →   Code (мала розмірність)   →   Вихід (велика розмірність)
  28×28 = 784 числа       →        4 числа              →      28×28 = 784 числа

        ENCODER                   LATENT SPACE                    DECODER
  (стискає дані)             (прихований простір)             (відновлює дані)
```

**Три основні компоненти:**

| Компонент | Роль | Аналогія |
| --------- | ---- | -------- |
| **Encoder** | Стискає вхід `X` → код `z` низької розмірності | «Переказ» довгого тексту у короткий конспект |
| **Code / Latent Space** | Вектор `z` — компактне числове представлення | Сам конспект |
| **Decoder** | Відновлює код `z` → реконструкцію `X̂` | «Розгортання» конспекту назад у повний текст |

#### Reconstruction Loss

Автокодер навчається мінімізуючи **похибку реконструкції** між вхідним `X` і відновленим `X̂`:

**Для дійсних значень (зображення, нормалізовані до [0,1]):**
```
MSE = (1/n) · Σ (X - X̂)²
```

**Для бінарних / категоріальних даних:**
```
BCE = -Σ [ X · log(X̂) + (1-X) · log(1-X̂) ]
```

> **В нашому практичному прикладі** з Fashion-MNIST: зображення нормалізовані до [0,1] → використовуємо `MSELoss`. Чим менший MSE — тим ближче реконструкція до оригіналу.

---

### 2.2 Де застосовуються автокодери

| Задача | Як використовується автокодер |
| ------ | ----------------------------- |
| **Видалення шуму (denoising)** | Навчаємо на парах «шумне → чисте»; encoder ігнорує шум, decoder відновлює чисте зображення |
| **Підвищення роздільної здатності (super-resolution)** | Decoder навчається генерувати більший вихід, ніж вхід encoder |
| **Розфарбовування (colorization)** | Encoder обробляє ч/б зображення; decoder генерує кольоровий варіант |
| **Видалення водяних знаків** | Аналогічно до denoising: encoder «не помічає» watermark |
| **Стиснення даних** | Зберігаємо тільки `z` (latent code) — набагато менший за оригінал |
| **Зниження розмірності** | Latent space з 4–64 вимірів замість 784 — зручно для візуалізації та аналізу |
| **Виявлення аномалій** | Модель погано відновлює аномальні приклади → великий MSE = аномалія |
| **Кластеризація** | Точки в latent space можна кластеризувати (K-means, DBSCAN тощо) |
| **Генерація нових даних** | Семплюємо з latent space і декодуємо (краще для VAE, ніж для звичайного AE) |

---

### 2.3 Властивості і гіперпараметри

**Дві ключові властивості автокодерів:**

1. **Залежність від даних (data-specific):** автокодер ефективно стискає тільки дані, схожі на тренувальні. AE, навчений на одязі, погано стиснить обличчя.

2. **Кодування з втратами (lossy compression):** реконструкція `X̂` завжди гірша за оригінал `X`. Чим менший latent space — тим більші втрати.

**Основні гіперпараметри:**

| Гіперпараметр | Що впливає | Типові значення |
| ------------- | ---------- | --------------- |
| **Розмір code (dim)** | Ступінь стиснення; чим менший — тим більше втрат | 4, 16, 64, 128 |
| **Кількість шарів** | Глибина encoder/decoder | 2–5 шарів |
| **Кількість вузлів/фільтрів** | Ємність мережі | 8, 16, 32, 64, 128, 256 |
| **Функція втрат** | Залежить від типу даних | MSE, BCE |
| **Learning rate** | Швидкість навчання | 1e-3, 1e-4 |
| **Batch size** | Стабільність градієнта | 64, 128, 256 |

> **Правило:** decoder зазвичай симетричний до encoder за структурою (ті самі кількості шарів, але у зворотному порядку). Це не суворе правило, але є поширеною практикою.

## ЧАСТИНА 3. ЗГОРТКОВІ АВТОКОДЕРИ ТА ТРАНСПОНОВАНА ЗГОРТКА

### 3.1 Конволюційний автокодер (CAE)

**Convolutional Autoencoder (CAE)** — автокодер, де і encoder, і decoder використовують **згорткові шари** замість лише повнозв'язних. Це ефективніше для зображень, бо:

- Зберігає **просторову структуру** (локальні залежності пікселів)
- Параметрів значно менше, ніж у повнозв'язному AE
- Backbone CNN вивчає **ієрархічні ознаки**: краї → форми → частини об'єктів

![Convolutional Autoencoder: encoder (Conv+stride) → latent code → decoder (ConvTranspose)](images/conv_autoencoder_architecture.png)

*Zgörтковий автокодер: вхідне зображення → Conv шари зі stride (зменшення) → latent code → FC шар → Unflatten → ConvTranspose шари (збільшення) → реконструкція.*

**Архітектура нашого CAE (Fashion-MNIST, dim=4):**

```
ENCODER:
28×28×1
  ↓ Conv2d(1→8,  3×3, stride=2, padding=1) + ReLU        → 14×14×8
  ↓ Conv2d(8→16, 3×3, stride=2, padding=1) + BN + ReLU   → 7×7×16
  ↓ Conv2d(16→32,3×3, stride=2, padding=0) + ReLU        → 3×3×32
  ↓ Flatten                                               → 288 (= 3×3×32)
  ↓ Linear(288→128) + ReLU                                → 128
  ↓ Linear(128→4)                                         → 4   ← latent code

DECODER:
4
  ↓ Linear(4→128) + ReLU                                  → 128
  ↓ Linear(128→288) + ReLU                                → 288
  ↓ Unflatten(32, 3, 3)                                   → 3×3×32
  ↓ ConvTranspose2d(32→16, 3×3, stride=2) + BN + ReLU    → 7×7×16
  ↓ ConvTranspose2d(16→8, 3×3, stride=2, p=1, op=1) + BN+ReLU → 14×14×8
  ↓ ConvTranspose2d(8→1, 3×3, stride=2, p=1, op=1) + Sigmoid  → 28×28×1
```

> **Чому stride=2 замість MaxPool?** MaxPool відкидає просторову інформацію безповоротньо. Stride=2 у Conv2d — це trainable downsampling: мережа сама вчиться, яку інформацію зберігати.

> **Чому Sigmoid на виході декодера?** Fashion-MNIST нормалізований до [0,1]. Sigmoid притискає вихід до [0,1] — піксельні значення залишаються коректними. MSELoss очікує значення в тому ж діапазоні, що і вхід (також [0,1] після `ToTensor()`).

---

### 3.2 Транспонована згортка (ConvTranspose2d)

**Транспонована згортка** — ключова операція для декодера: вона **збільшує** просторовий розмір feature map. Також відома як «деконволюція» або «upsampling convolution».

> **Важливо:** «деконволюція» — популярна, але технічно неточна назва. Транспонована згортка — **не** математична обернена операція до згортки. Вона просто збільшує розмір за допомогою навчених фільтрів.

#### Анімація механізму

![Транспонована згортка без padding і stride: 2×2 вхід → 4×4 вихід](images/no_padding_no_strides_transposed.gif)

*Транспонована згортка (no padding, no strides, kernel 3×3): синій — 2×2 вхід, блакитний — 4×4 вихід. Кожен піксель вхідного «розширюється» через фільтр, результати в областях перекриття додаються.*

#### Покроковий механізм

```
Вхідний піксель = a               Фільтр 3×3:
                                   [ w1 w2 w3 ]
Множимо піксель a на фільтр:       [ w4 w5 w6 ]
                                   [ w7 w8 w9 ]

Результат для пікселя a:
[ a·w1  a·w2  a·w3 ]    ← записуємо у відповідні позиції виходу
[ a·w4  a·w5  a·w6 ]
[ a·w7  a·w8  a·w9 ]

Те саме для пікселів b, c, d → де результати накладаються — додаємо
```

#### Формула вихідного розміру

```
output_size = (input_size - 1) × stride - 2 × padding + kernel_size + output_padding
```

**Приклади з нашого декодера:**

| Шар | input | stride | padding | kernel | output_padding | output |
| --- | ----- | ------ | ------- | ------ | -------------- | ------ |
| ConvTranspose2d(32→16) | 3 | 2 | 0 | 3 | 0 | (3-1)×2 - 0 + 3 + 0 = **7** |
| ConvTranspose2d(16→8) | 7 | 2 | 1 | 3 | 1 | (7-1)×2 - 2 + 3 + 1 = **14** |
| ConvTranspose2d(8→1) | 14 | 2 | 1 | 3 | 1 | (14-1)×2 - 2 + 3 + 1 = **28** |

> **Навіщо `output_padding`:** при певних комбінаціях `stride` і `input_size` вихідний розмір може бути неоднозначним (наприклад, і 13, і 14 дають однаковий вхід при stride=2). `output_padding` додає 0 або 1 піксель на правому/нижньому краю виходу, щоб отримати точний розмір.

**Корисний ресурс:** інтерактивні анімації всіх конфігурацій:
[conv_arithmetic](https://github.com/vdumoulin/conv_arithmetic/blob/master/README.md)

---

### 3.3 ConvTranspose2d vs Upsample + Conv

Два поширені підходи до upsampling у декодерах:

| Підхід | Як працює | Плюси | Мінуси |
| ------ | --------- | ----- | ------- |
| `ConvTranspose2d` | Trainable upsampling | Гнучкий, навчається | Може давати «шахівний» артефакт (checkerboard) |
| `Upsample(scale=2) + Conv2d` | Білінійний upsampling + звичайна згортка | Менше артефактів | Дещо більше параметрів |

У нашому автокодері використовується `ConvTranspose2d` — класичний та поширений підхід.

## ЧАСТИНА 5. ПРАКТИКА — ВИЗНАЧЕННЯ МОДЕЛІ

### 5.1 Клас Encoder

```python
class Encoder(nn.Module):
    """
    Encoder: стискає зображення 28×28×1 → latent vector розміру encoded_space_dim.
    Складається з трьох Conv2d шарів (зменшення просторового розміру) +
    двох Linear шарів (перехід до latent code).
    """

    def __init__(self, encoded_space_dim, fc2_input_dim):
        """
        encoded_space_dim: розмір latent code (у нас = 4)
        fc2_input_dim:     розмір проміжного FC шару (у нас = 128, але не використовується
                           напряму як параметр у цій реалізації)
        """
        super().__init__()

        # --- Згорткова частина ---
        self.encoder_cnn = nn.Sequential(
            # Шар 1: 1 канал → 8 каналів, ядро 3×3, stride=2, padding=1
            # Розмір: 28×28×1 → 14×14×8
            nn.Conv2d(1, 8, 3, stride=2, padding=1),
            # nn.BatchNorm2d(8),  ← закоментовано навмисно (не симетрично до decoder)
            nn.ReLU(True),  # inplace=True — економить пам'ять, змінює тензор на місці

            # Шар 2: 8 каналів → 16 каналів, stride=2, padding=1
            # Розмір: 14×14×8 → 7×7×16
            nn.Conv2d(8, 16, 3, stride=2, padding=1),
            nn.BatchNorm2d(16),  # BatchNorm: стабілізує навчання, прискорює збіжність
            nn.ReLU(True),

            # Шар 3: 16 каналів → 32 канали, stride=2, padding=0
            # Розмір: 7×7×16 → 3×3×32 (без padding: (7-3)/2 + 1 = 3)
            nn.Conv2d(16, 32, 3, stride=2, padding=0),
            # nn.BatchNorm2d(32),  ← закоментовано навмисно
            nn.ReLU(True)
        )

        # --- Flatten шар ---
        # Перетворює тензор [batch, 32, 3, 3] → [batch, 288]
        # start_dim=1: починаємо flatten з першого (не batch) виміру
        self.flatten = nn.Flatten(start_dim=1)

        # --- Лінійна частина ---
        self.encoder_lin = nn.Sequential(
            # Шар 1: 288 → 128
            nn.Linear(3 * 3 * 32, 128),  # 3*3*32 = 288
            nn.ReLU(True),
            # Шар 2: 128 → encoded_space_dim (4)
            nn.Linear(128, encoded_space_dim)
            # Немає активації на виході — latent code може бути будь-яким числом
        )

    def forward(self, x):
        x = self.encoder_cnn(x)    # Застосовуємо Conv шари: [B,1,28,28] → [B,32,3,3]
        x = self.flatten(x)        # Flatten: [B,32,3,3] → [B,288]
        x = self.encoder_lin(x)    # Linear: [B,288] → [B,4]
        return x
```

### 5.2 Клас Decoder

```python
class Decoder(nn.Module):
    """
    Decoder: відновлює зображення з latent vector (encoded_space_dim) → 28×28×1.
    Симетричний до Encoder: спочатку Linear шари (розширення),
    потім ConvTranspose2d шари (збільшення просторового розміру).
    """

    def __init__(self, encoded_space_dim, fc2_input_dim=128):
        """
        encoded_space_dim: розмір latent code (= 4, такий самий як у Encoder)
        fc2_input_dim:     розмір проміжного FC шару (за замовчуванням 128)
        """
        super().__init__()

        # --- Лінійна частина ---
        self.decoder_lin = nn.Sequential(
            # Шар 1: encoded_space_dim (4) → 128
            nn.Linear(encoded_space_dim, 128),
            nn.ReLU(True),
            # Шар 2: 128 → 288 (= 3×3×32)
            nn.Linear(128, 3 * 3 * 32),
            nn.ReLU(True)
        )

        # --- Unflatten шар ---
        # Перетворює [batch, 288] → [batch, 32, 3, 3]
        # dim=1: розгортаємо перший (не batch) вимір
        # unflattened_size=(32, 3, 3): цільова форма
        self.unflatten = nn.Unflatten(dim=1, unflattened_size=(32, 3, 3))

        # --- Транспонована згорткова частина ---
        self.decoder_conv = nn.Sequential(
            # Шар 1: 32 → 16, stride=2
            # Розмір: 3×3×32 → 7×7×16
            # Формула: (3-1)×2 - 2×0 + 3 + 0 = 7 ✓
            nn.ConvTranspose2d(32, 16, 3, stride=2, output_padding=0),
            nn.BatchNorm2d(16),
            nn.ReLU(True),

            # Шар 2: 16 → 8, stride=2, padding=1, output_padding=1
            # Розмір: 7×7×16 → 14×14×8
            # Формула: (7-1)×2 - 2×1 + 3 + 1 = 14 ✓
            nn.ConvTranspose2d(16, 8, 3, stride=2, padding=1, output_padding=1),
            nn.BatchNorm2d(8),
            nn.ReLU(True),

            # Шар 3: 8 → 1, stride=2, padding=1, output_padding=1
            # Розмір: 14×14×8 → 28×28×1
            # Формула: (14-1)×2 - 2×1 + 3 + 1 = 28 ✓
            nn.ConvTranspose2d(8, 1, 3, stride=2, padding=1, output_padding=1)
            # Немає ReLU — використовуємо Sigmoid у forward()
        )

    def forward(self, x):
        x = self.decoder_lin(x)     # Linear: [B,4] → [B,288]
        x = self.unflatten(x)       # Unflatten: [B,288] → [B,32,3,3]
        x = self.decoder_conv(x)    # ConvTranspose: [B,32,3,3] → [B,1,28,28]
        # Sigmoid: обмежує вихід [0,1] — відповідає нормалізованим пікселям
        x = torch.sigmoid(x)
        return x
```

> **Warning:** `BatchNorm2d(8)` і `BatchNorm2d(32)` у Encoder закоментовані навмисно. Тому архітектура encoder і decoder **не повністю симетрична**. Це не помилка — просто один з варіантів, який добре навчається.

## ЧАСТИНА 6. ПРАКТИКА — НАВЧАННЯ МОДЕЛІ

### 6.1 Компоненти навчання

```python
# --- Функція втрат ---
# MSELoss: середньоквадратична похибка між реконструкцією і оригіналом
# Обчислює середнє (X - X̂)² по всіх пікселях і батчу
loss_fn = torch.nn.MSELoss()

# --- Оптимізатор ---
# Adam (Adaptive Moment Estimation) — поширений вибір для автокодерів
# lr=0.001: learning rate — крок градієнтного спуску
# weight_decay=1e-05: L2 регуляризація — штрафує великі ваги, зменшує перенавчання

lr = 0.001

# Передаємо параметри і encoder, і decoder — навчаються одночасно
params_to_optimize = [
    {'params': encoder.parameters()},  # Усі trainable параметри encoder
    {'params': decoder.parameters()}   # Усі trainable параметри decoder
]

optim = torch.optim.Adam(params_to_optimize, lr=lr, weight_decay=1e-05)
```

### 6.2 Функції train_epoch і test_epoch

```python
def train_epoch(encoder, decoder, device, dataloader, loss_fn, optimizer):
    """
    Виконує одну епоху навчання: один прохід по всьому тренувальному датасету.

    encoder:    об'єкт Encoder
    decoder:    об'єкт Decoder
    device:     пристрій (cpu або cuda)
    dataloader: DataLoader для тренувальних даних
    loss_fn:    функція втрат (MSELoss)
    optimizer:  оптимізатор (Adam)

    Повертає: середній train loss за епоху (float)
    """
    # Переводимо в режим тренування (BatchNorm і Dropout поводяться по-іншому)
    encoder.train()
    decoder.train()
    train_loss = []

    # Ітеруємо по батчах; _ — ігноруємо мітки (unsupervised learning)
    for image_batch, _ in dataloader:
        # 1. Переміщуємо батч на правильний пристрій
        image_batch = image_batch.to(device)

        # 2. Кодуємо: [B,1,28,28] → [B,4]
        encoded_data = encoder(image_batch)

        # 3. Декодуємо: [B,4] → [B,1,28,28]
        decoded_data = decoder(encoded_data)

        # 4. Обчислюємо reconstruction loss між реконструкцією і оригіналом
        loss = loss_fn(decoded_data, image_batch)

        # 5. Обнуляємо градієнти (важливо робити перед backward!)
        optimizer.zero_grad()

        # 6. Зворотне поширення: обчислюємо градієнти loss по всіх параметрах
        loss.backward()

        # 7. Крок оптимізатора: оновлюємо ваги
        optimizer.step()

        # Логуємо loss поточного батчу
        print('\t partial train loss (single batch): %f' % (loss.data))
        train_loss.append(loss.detach().cpu().numpy())  # Зберігаємо для усереднення

    return np.mean(train_loss)  # Повертаємо середній loss по всіх батчах
```

```python
def test_epoch(encoder, decoder, device, dataloader, loss_fn):
    """
    Обчислює reconstruction loss на validation або test вибірці.
    Не оновлює ваги — тільки оцінює якість.

    Повертає: loss (torch.Tensor)
    """
    # Переводимо в режим оцінки (BatchNorm використовує накопичену статистику)
    encoder.eval()
    decoder.eval()

    with torch.no_grad():  # Вимикаємо обчислення градієнтів → економія пам'яті і часу
        conc_out = []    # Список реконструйованих батчів
        conc_label = []  # Список оригінальних батчів

        for image_batch, _ in dataloader:
            image_batch = image_batch.to(device)
            encoded_data = encoder(image_batch)
            decoded_data = decoder(encoded_data)
            # Переміщуємо результати на CPU для накопичення (GPU пам'ять обмежена)
            conc_out.append(decoded_data.cpu())
            conc_label.append(image_batch.cpu())

        # Об'єднуємо всі батчі в один великий тензор
        conc_out = torch.cat(conc_out)
        conc_label = torch.cat(conc_label)

        # Обчислюємо loss на всій вибірці (не по батчах)
        val_loss = loss_fn(conc_out, conc_label)

    return val_loss.data
```

**Пояснення ключових методів:**

| Метод | Що робить |
| ----- | --------- |
| `encoder.train()` / `decoder.train()` | Вмикає режим навчання: BatchNorm оновлює статистику, Dropout активний |
| `encoder.eval()` / `decoder.eval()` | Вмикає режим оцінки: BatchNorm використовує накопичену статистику |
| `torch.no_grad()` | Контекстний менеджер: вимикає обчислення графа градієнтів |
| `optimizer.zero_grad()` | Обнуляє накопичені градієнти (PyTorch накопичує, не замінює) |
| `loss.backward()` | Зворотне поширення: обчислює ∂loss/∂w для всіх параметрів |
| `optimizer.step()` | Оновлює ваги на основі градієнтів |
| `loss.detach().cpu().numpy()` | Від'єднує від графа → переміщує на CPU → конвертує у numpy |
| `torch.cat(list)` | Конкатенує список тензорів в один вздовж першого виміру |

## ЧАСТИНА 7. ПРАКТИКА — ГЕНЕРАЦІЯ НОВИХ ЗОБРАЖЕНЬ

### 7.1 Концепція: семплінг із латентного простору

Ідея: якщо encoder відображає зображення у точки `z` в 4-вимірному просторі, то довільні точки в цьому просторі теж можна «декодувати» у нові зображення.

**Метод:** знаходимо середнє `μ` і стандартне відхилення `σ` latent кодів для кількох тестових зображень, а потім семплюємо нові `z` з нормального розподілу `N(μ, σ²)`:

```
z_new = randn(dim) × σ + μ
```

### 7.2 Функції show_image і show_top_n

```python
def show_image(img):
    """
    Відображає один батч зображень у вигляді сітки.
    img: тензор від torchvision.utils.make_grid (C×H×W)
    """
    npimg = img.numpy()  # Конвертуємо тензор у numpy для matplotlib
    # make_grid повертає [C, H, W]; plt.imshow очікує [H, W, C]
    # np.transpose переставляє виміри: (1,2,0) = (H, W, C)
    plt.imshow(np.transpose(npimg, (1, 2, 0)))


def show_top_n(encoder, decoder, dataset, n=10):
    """
    Генерує нові зображення, семплюючи з латентного простору.

    encoder, decoder: навчені об'єкти
    dataset: датасет для обчислення mid/std latent code
    n: кількість зображень для обчислення статистики
    """
    encoder.eval()
    decoder.eval()

    with torch.no_grad():
        # 1. Кодуємо перші n зображень датасету
        images, labels = map(list, zip(*[dataset[i] for i in range(n)]))
        # map(list, ...) конвертує zip-об'єкт у два списки
        # zip(*...) розпаковує список пар (img, label) у два окремі ітерабельні
        images = torch.stack(images).to(device)  # Збираємо список тензорів у батч
        latent = encoder(images)  # Отримуємо latent коди: [n, dim]
        latent = latent.cpu()

        # 2. Обчислюємо статистику latent space
        mean = latent.mean(dim=0)  # Середнє по batch виміру: [dim]
        print(mean)
        std = (latent - mean).pow(2).mean(dim=0).sqrt()  # Стандартне відхилення: [dim]
        print(std)

        # 3. Семплюємо 128 нових latent векторів з нормального розподілу
        # torch.randn(128, dim): 128 векторів з N(0,1)
        # * std + mean: масштабуємо і зсуваємо до N(mean, std²)
        latent = torch.randn(128, dim) * std + mean

        # 4. Декодуємо нові latent вектори
        latent = latent.to(device)
        img_recon = decoder(latent)  # [128, 1, 28, 28]
        img_recon = img_recon.cpu()

        # 5. Відображаємо перші 100 із 128 згенерованих зображень у сітці 10×10
        fig, ax = plt.subplots(figsize=(20, 8.5))
        show_image(torchvision.utils.make_grid(img_recon[:100], 10, 5))
        # make_grid(tensor, nrow, padding): nrow=10 зображень у рядку, padding=5 пікселів між
        plt.show()


show_top_n(encoder, decoder, test_dataset, n=10)
```

**Пояснення методів:**

| Метод | Параметри | Що робить |
| ----- | --------- | --------- |
| `torch.stack(list)` | список тензорів | Об'єднує список тензорів у новий батч-вимір |
| `latent.mean(dim=0)` | `dim=0`: по batch | Середнє по batch виміру → вектор розміру `[dim]` |
| `.pow(2)` | — | Підносить кожен елемент до квадрату |
| `.sqrt()` | — | Квадратний корінь з кожного елемента |
| `torch.randn(128, dim)` | — | 128 × dim матриця з N(0,1) |
| `torchvision.utils.make_grid(tensor, nrow, padding)` | `nrow`: кількість зображень у рядку | Збирає батч зображень у єдине зображення-сітку |

![100 зображень, згенерованих із латентного простору автокодера](images/generated_from_latent.png)

*100 нових зображень, декодованих із точок у латентному просторі (семплінг із N(μ, σ²)). Деякі нагадують одяг, деякі — безглузді.*

**Як читати:**
- Деякі зображення схожі на одяг (сорочки, штани, взуття) — decoder «впізнає» семпли, близькі до тренувальних даних.
- Частина зображень виглядає безглуздо — бо latent space **нерегулярний**: між реальними точками можуть бути «порожні» зони, де decoder не знає, що генерувати.

#### Чому AE погано підходить для генерації

> **Ключовий висновок:** звичайний автокодер навчається відображати конкретні зображення в конкретні точки latent space. Між цими точками можуть бути «порожні» зони, де decoder не має чіткого навчального сигналу → генерує безглуздя.
>
> **Рішення:** Variational Autoencoder (VAE) — регуляризує latent space так, щоб він був «безперервним» і нормально розподіленим. Будь-яка точка в такому просторі декодується у щось осмислене. VAE — тема наступних лекцій.

```
Звичайний AE:          VAE:
  x₁ → z₁               x₁ → μ₁ ± σ₁  (розподіл, не точка)
  x₂ → z₂               x₂ → μ₂ ± σ₂
  ↑                      ↑
між z₁ і z₂             latent простір «щільний»
можуть бути             → семплінг дає осмислені
«порожні» місця         зображення скрізь
```

  - Ключова властивість: залежність від даних і кодування з втратами.

  - Генерація з латентного простору: частина зображень осмислена, частина — ні.
  - Причина: AE має нерегулярний latent space → для генерації краще VAE.

### 1) AP і mAP — швидко

- `AP` = площа під PR-кривою для **одного класу**
- `mAP` = середнє AP по **всіх класах**
- `mAP@0.5` = AP при IoU ≥ 0.5 (один IoU threshold — «легкий» варіант)
- `mAP@0.50:0.95` = середнє по IoU 0.50, 0.55, ..., 0.95 (строгий COCO-критерій)
- `F1 = 2·P·R/(P+R)` — максимізується при оптимальному confidence threshold

### 2) Читання графіків YOLO

| Графік | Що шукати |
| ------ | --------- |
| `F1_curve` | Де максимум F1 → оптимальний conf threshold |
| `PR_curve` | AP по класах; слабкі класи мають низький AP |
| `P_curve` | Зростає → 1 при conf → 1 (модель впевнена = точна) |
| `R_curve` | Спадає при conf → 1 (суворий поріг = більше пропусків) |
| `confusion_matrix_normalized` | Діагональ = recall по класах; колонка background = пропуски |
| `results.png` | Чи спадають всі loss? Чи зростають метрики? Перенавчання? |

### 3) Автокодер — must know

```
Input X  →  [Encoder]  →  Code z  →  [Decoder]  →  X̂ (реконструкція)
             стискає           відновлює
```

- Навчання: мінімізація reconstruction loss = MSE(X, X̂)
- Latent space = компактне представлення суті вхідних даних
- **Без міток** (unsupervised learning)

### 4) Транспонована згортка (ConvTranspose2d)

- Збільшує просторовий розмір (протилежна до Conv2d зі stride)
- `output = (in - 1) × stride - 2 × padding + kernel + output_padding`
- Stride=2 → розмір × 2 (приблизно)
- `output_padding` потрібен для точного відновлення непарних розмірів

### 5) Форми тензорів нашого CAE

```
Encoder:  [B,1,28,28] → [B,8,14,14] → [B,16,7,7] → [B,32,3,3] → [B,288] → [B,128] → [B,4]
Decoder:  [B,4] → [B,128] → [B,288] → [B,32,3,3] → [B,16,7,7] → [B,8,14,14] → [B,1,28,28]
```

### 6) Чому AE погано генерує і навіщо VAE

- AE: кожне зображення → одна точка в latent space → між точками «порожні» зони
- VAE: кожне зображення → розподіл (μ, σ) → regularized latent space → будь-яка точка осмислена

### 7) Типові пастки коду

- `optim = torch.optim.Adam(...)` перезаписує модуль `optim` → пиши `torch.optim.Adam()` далі
- `encoder.to(device)` і `decoder.to(device)` окремо — вони незалежні `nn.Module`
- `image_batch.to(device)` у циклі — батчі теж потрібно переносити
- `plot_ae_outputs` читає `test_dataset`, `device`, `dim` з глобальної області
- `data_dir = 'data'` для Colab/локально; `'../data'` для Kaggle
- `BatchNorm2d(8)` і `(32)` у Encoder закоментовані — це **навмисно**, не помилка
