## ЧАСТИНА 1. ОДНО- ТА ДВОЕТАПНІ ПІДХОДИ

### Що таке детекція об'єктів?

**Детекція об'єктів** (Object Detection) — це задача комп'ютерного зору, яка поєднує:

- **класифікацію** — «що це?» (людина, машина, каска тощо)
- **локалізацію** — «де це?» (координати bounding box)

Тобто на відміну від класифікації (один клас на всє зображення), детектор знаходить **усі** об'єкти на зображенні й окреслює кожен прямокутником.


| Задача       | Вхід       | Вихід                | Складність |
| ------------ | ---------- | -------------------- | ---------- |
| Класифікація | Зображення | 1 клас               | Нижча      |
| Детекція     | Зображення | N рамок + N класів   | Вища       |
| Сегментація  | Зображення | Клас кожного пікселя | Найвища    |


### Двоетапні підходи (Two-Stage)

```
Зображення → [ЕТАП 1: Генерація регіонів-кандидатів] → [ЕТАП 2: Класифікація кожного регіону]
```

**Як це працює:**

- **Етап 1** — алгоритм (Selective Search або RPN) пропонує ~2000 зон, де можуть бути об'єкти
- **Етап 2** — CNN аналізує кожну зону, класифікує й уточнює рамку

**Приклади:** R-CNN, Fast R-CNN, Faster R-CNN


| Переваги                                   | Недоліки                                      |
| ------------------------------------------ | --------------------------------------------- |
| Висока точність детекції                   | Повільні — два окремих етапи                  |
| Гнучкість: кожен етап можна вдосконалювати | Складна архітектура і налаштування            |
| Добре працюють зі складними сценами        | Не підходять для застосувань у реальному часі |


### Одноетапні підходи (Single-Stage)

```
Зображення → [Один прохід через CNN → одночасно: регіони + класи + рамки]
```

**Як це працює:**

- Зображення ділиться на **сітку** комірок
- Кожна комірка одночасно прогнозує наявність об'єкта, його клас і координати рамки
- Не потрібен окремий етап генерації регіонів

**Приклади:** YOLO, SSD, RetinaNet


| Переваги                                     | Недоліки                                              |
| -------------------------------------------- | ----------------------------------------------------- |
| Дуже швидкі — підходять для реального часу   | Нижча точність на складних сценах                     |
| Простіша архітектура                         | Проблеми з виявленням дуже малих або великих об'єктів |
| Легко інтегруються в пристрої (edge devices) | Схильність до дисбалансу класів (багато фону)         |


### Як обрати підхід?


| Вимога                                           | Рекомендація              |
| ------------------------------------------------ | ------------------------- |
| Реальний час (відеоспостереження, авто)          | YOLO, SSD (одноетапні)    |
| Максимальна точність (медицина, контроль якості) | Faster R-CNN (двоетапний) |
| Обмежені ресурси (мобільний пристрій)            | YOLOv8n / MobileNet SSD   |
| Дисбаланс класів + точність                      | RetinaNet з Focal Loss    |

### 2.1 R-CNN (Region-based Convolutional Neural Network)

**R-CNN** — перша архітектура, що об'єднала пропозиції регіонів з CNN для детекції. Представлена **Россом Гіршиком** та колегами у **2014 році**.

- Оригінальна стаття: [тема_7/R_CNN.pdf](R_CNN.pdf)
- Детальний опис: [GeeksforGeeks: R-CNN](https://www.geeksforgeeks.org/machine-learning/r-cnn-region-based-cnns/)

![R-CNN pipeline: 4 кроки детекції](images/r_cnn_pipeline.png)

*Чотири кроки R-CNN: вхідне зображення → ~2000 регіонів → CNN-ознаки → класифікація*

---

#### Крок 1. Генерація регіонів-кандидатів (Selective Search)

Перший крок — знайти потенційні місця, де можуть бути об'єкти. Для цього використовується алгоритм **Selective Search**.

![Selective Search: сегментація зображення і виділення регіонів](images/selective_search.png)

*Selective Search групує пікселі в регіони (ліворуч) і генерує bounding boxes (праворуч)*

**Як працює Selective Search — детальна схема (англ.):**

![Selective Search: покроковий алгоритм — graph-based segmentation, hierarchical merging, region proposals](images/selective_search_en.jpg)

**Той самий алгоритм українською:**

![Selective Search: початкова сегментація, рекурсивне об'єднання регіонів, регіони-кандидати](images/selective_search_uk.jpg)

**Як працює Selective Search:**

**Крок 1. Початкова сегментація (graph-based segmentation)**

Зображення ділиться на багато маленьких однорідних областей за допомогою алгоритму **Felzenszwalb–Huttenlocher**:

- Кожен піксель → вузол графа
- Сусідні пікселі з'єднані ребрами; для кожного ребра рахується «відмінність» між пікселями (наприклад, кольорова відстань)
- Якщо сусідні пікселі достатньо схожі → їх об'єднують в один регіон

Приклад для двох пікселів:

```
pixel A = [120, 80, 60]
pixel B = [125, 82, 58]
distance = sqrt((120-125)² + (80-82)² + (60-58)²)  # ≈ 5.7 → мала відмінність → один регіон
```

> **Важливо:** це **не CNN**. Selective Search не використовує trainable weights і не виконує матричне множення. Він працює з числовими значеннями пікселів через класичні алгоритми сегментації.
>
> Порівняння:
>
> - **CNN** — ядро ковзає по зображенню і рахує feature maps через навчені ваги
> - **Selective Search** — ділить зображення на сегменти, потім об'єднує схожі сусідні сегменти

**Крок 2. Рекурсивне об'єднання сусідніх регіонів**

Алгоритм оцінює схожість сусідніх регіонів за **чотирма критеріями**:


| Критерій               | Що оцінює                                                     |
| ---------------------- | ------------------------------------------------------------- |
| **Color similarity**   | Схожість розподілів кольорів у регіонах                       |
| **Texture similarity** | Схожість текстур (гладка/зерниста тощо)                       |
| **Size similarity**    | Чи мають регіони сумісний розмір                              |
| **Fill similarity**    | Наскільки добре два регіони разом утворюють компактну область |


Якщо регіони достатньо схожі — вони об'єднуються:

```
[небо₁] [небо₂] → [небо]
[корова₁] [корова₂] → [тулуб корови] → [вся корова]
[трава₁] [трава₂] [трава₃] → [трава]
```

Алгоритм повторює це ітеративно:

```
маленькі сегменти → більші сегменти → ще більші → різні можливі групи
```

**Крок 3. Генерація region proposals**

Selective Search **не вибирає одну правильну сегментацію**. Він зберігає багато варіантів на різних рівнях злиття:

```
[голова корови]
[тулуб корови]
[голова + тулуб]
[вся корова]
[корова + трохи трави]
...
```

Для кожної такої області будується bounding box → це і є **region proposals**.

> **Ключова ідея Selective Search:**
>
> Він не каже «О, це корова». Він каже: «Ось ця область візуально цілісна і може містити якийсь об'єкт — передамо її CNN».
>
> Мета — згенерувати достатньо розумних кандидатів, щоб серед них майже напевно був прямокутник навколо справжнього об'єкта. А вже CNN питає: «Що тут — корова, машина чи фон?»

**Повна схема:**

```
IMAGE
  ↓
graph-based segmentation (маленькі однорідні регіони)
  ↓
оцінка схожості сусідніх регіонів (color + texture + size + fill)
  ↓
об'єднання схожих → більші регіони
  ↓
збереження багатьох варіантів злиття
  ↓
bounding boxes для кожного варіанту
  ↓
REGION PROPOSALS (~2000)
  ↓
CNN класифікує кожен proposal
```

> **Чому так багато рамок на зображенні?** Це навмисно — алгоритм генерує кандидатів різного розміру, щоб не пропустити жодного реального об'єкта.

> **Результат:** ~2000 регіонів на одне зображення, які охоплюють більшість реальних об'єктів.

#### Крок 2. Виділення ознак за допомогою CNN

Кожен із ~2000 регіонів **нормалізується** до розміру 227×227 і передається через попередньо навчену CNN (AlexNet, навчену на ImageNet).

![R-CNN: AlexNet для виділення ознак з кожної пропозиції](images/r_cnn_alexnet.png)

*Кожна область пропозиції → AlexNet → вектор ознак розміром 4096*

- Останній повнозв'язний шар (`fc7`) видаляється → залишається вектор розміром **4096**
- Цей вектор є компактним представленням вмісту регіону

> **Примітка щодо ефективності:** кожне з ~2000 зображень обробляється окремо → це **дуже повільно** (~49 сек на зображення).

#### Крок 3. Класифікація за допомогою SVM

![R-CNN: окремий ConvNet + SVM + bbox regressor для кожного регіону](images/r_cnn_region_proposals.jpg)

*Для кожного регіону-кандидата запускається свій ConvNet, після чого SVM класифікує об'єкт*

Вектор ознак розміром 4096 передається в набір **бінарних SVM-класифікаторів** — окремий для кожного класу.

##### Що таке SVM?

> **SVM (Support Vector Machine)** — алгоритм машинного навчання, який шукає **гіперплощину** (лінію, площину або гіперплощину у n-вимірному просторі), яка **якнайкраще розділяє** точки двох класів.
>
> **Ключові поняття:**
>
> - **Опорні вектори (support vectors)** — найближчі до межі точки з кожного класу. Саме вони визначають положення гіперплощини.
> - **Маржа (margin)** — відстань між гіперплощиною та найближчими опорними векторами. SVM максимізує цю відстань.
> - **Ядро (kernel)** — трюк для роботи з нелінійно роздільними даними: `linear`, `poly`, `rbf` тощо.
> - `**class_weight='balanced'**` — автоматично підвищує вагу рідшого класу при дисбалансі.
>
> У контексті R-CNN для кожного класу (наприклад, «людина», «машина») навчається **окремий бінарний SVM**: «є об'єкт цього класу» / «немає об'єкта».
>
> Детальний розбір SVM з кодом: [neo/ml/topic8_svm_petfinder.md](/Users/cordial/Documents/neo/ml/topic8_svm_petfinder.md)

#### Крок 4. Корекція рамок (Bounding Box Regression)

Окрім класифікації, для кожного регіону навчається **лінійна регресійна модель**, яка уточнює координати bounding box.

Модель отримує 4 значення `(x, y, w, h)` — центр і розміри рамки — і прогнозує **поправки**, що наближають рамку до реального об'єкта.

> **Навіщо:** алгоритм Selective Search не дає точних рамок — регресія покращує mAP на 3–4%.

#### Крок 5. Non-Maximum Suppression (NMS)

Після класифікації всіх ~2000 регіонів маємо багато рамок з різними оцінками впевненості. **NMS** прибирає зайві.

![NMS: до і після придушення зайвих рамок](images/nms.png)

*До NMS — багато рамок; після NMS — одна найкраща*

**Алгоритм NMS:**

1. Відкинути всі рамки з оцінкою впевненості (confidence score) нижче порогу (наприклад, 0.5)
2. Серед рамок, що залишились для одного класу, обрати **найвпевненішу**
3. Порівняти її з усіма іншими: якщо IoU > 0.5 — вважати їх дублікатами і видалити
4. Повторити з наступною за впевненістю рамкою

**Покроковий приклад:**

Модель знайшла одну корову трьома рамками:

```
Box A: confidence = 0.95
Box B: confidence = 0.88
Box C: confidence = 0.71
```

Крок 1 — беремо Box A (найвищий confidence).

Крок 2 — рахуємо IoU між Box A і рештою:

```
IoU(A, B) = 0.82   →   0.82 > 0.5   →   Box B — дублікат, видаляємо
IoU(A, C) = 0.20   →   0.20 < 0.5   →   Box C — інший об'єкт, залишаємо
```

Результат: залишились **Box A** і **Box C** — два різних об'єкти.

> **Важливо:** IoU > 0.5 не означає «50% однієї рамки всередині іншої». Це саме відношення Intersection / Union. Дві рамки, що дуже сильно перекриваються, мають IoU близько 1, навіть якщо жодна не повністю всередині іншої.

### 2.2 Метрика Intersection over Union (IoU)

Джерело: [pyimagesearch.com/2016/11/07/intersection-over-union-iou-for-object-detection](https://pyimagesearch.com/2016/11/07/intersection-over-union-iou-for-object-detection/)

![IoU: формула та візуалізація](images/iou_formula.png)

**IoU** вимірює, наскільки добре передбачена рамка збігається з еталонною.

```
IoU = площа перетину / площа об'єднання
    = Intersection / Union
```

- **Intersection (перетин)** — площа, яка одночасно належить обом рамкам
- **Union (об'єднання)** — загальна площа, яку покривають обидві рамки разом (без подвійного рахунку перетину)

**Приклад:** площа перетину = 40, площа об'єднання = 100 → IoU = 40/100 = **0.4**


| Значення IoU | Інтерпретація                                 |
| ------------ | --------------------------------------------- |
| = 0          | Рамки не перетинаються взагалі                |
| = 0.3        | Невелике перекриття                           |
| = 0.5        | Поріг «правильного» виявлення (True Positive) |
| = 0.8        | Дуже сильне перекриття — ймовірно, дублікат   |
| = 1.0        | Рамки повністю збігаються                     |


> **Правило:** IoU > 0.5 — «правильне» виявлення (True Positive). Саме цей поріг використовується у більшості задач.

**Детальна схема IoU з числовим прикладом:**

![IoU: що це, числовий приклад, приклади значень і зв'язок з NMS](images/iou_calculation_en.jpg)

*Схема: формула IoU (1), числовий розрахунок (2), приклади значень 0–1 (3), IoU threshold у NMS (4)*

**IoU і NMS — як вони пов'язані:**

![IoU і Non-Maximum Suppression: схема з порогом і прикладами](images/iou_nms_explained.jpg)

*Схема: що таке IoU (1), threshold у NMS (2) і як NMS крок за кроком прибирає дублікати (3)*

> **Нюанс:** IoU > threshold у NMS означає «ця рамка сильно перекривається з найкращою → вважаємо її дублікатом → видаляємо». IoU < threshold → рамки мало перекриваються → це, мабуть, **інший об'єкт** → залишаємо.

**Звідки назва «Non-Maximum Suppression»?**

> - **maximum** = рамка з **найвищим confidence score** — її залишаємо
> - **non-maximum** = всі інші рамки з меншим confidence
> - **suppression** = їхнє **пригнічення / видалення**
>
> Тобто: «залишити максимум і прибрати близькі до нього не-максимальні результати».
>
> Важливо: NMS видаляє **не всі** рамки з меншим confidence, а лише ті, що **сильно перекриваються** з кращою рамкою (IoU > threshold). Рамки, що слабо перекриваються, залишаються — вони можуть позначати інший об'єкт.

#### Реалізація IoU на Python

```python
def bb_intersection_over_union(boxA, boxB):
    """
    Обчислює IoU між двома bounding boxes.
    
    boxA, boxB: списки або кортежі формату [x_min, y_min, x_max, y_max]
    де (x_min, y_min) — лівий верхній кут, (x_max, y_max) — правий нижній.
    """
    # Координати перетину: беремо максимальні ліво/верхні і мінімальні право/нижні кути
    xA = max(boxA[0], boxB[0])
    yA = max(boxA[1], boxB[1])
    xB = min(boxA[2], boxB[2])
    yB = min(boxA[3], boxB[3])
    
    # Площа перетину: max(0, ...) захищає від від'ємних значень (рамки не перетинаються)
    interArea = max(0, xB - xA + 1) * max(0, yB - yA + 1)
    
    # Площі кожної рамки окремо
    boxAArea = (boxA[2] - boxA[0] + 1) * (boxA[3] - boxA[1] + 1)
    boxBArea = (boxB[2] - boxB[0] + 1) * (boxB[3] - boxB[1] + 1)
    
    # IoU = перетин / об'єднання. Від суми площ віднімаємо перетин (щоб не рахувати двічі)
    iou = interArea / float(boxAArea + boxBArea - interArea)
    
    return iou


# Приклад використання
boxA = [39, 63, 203, 112]   # еталонна рамка (ground truth)
boxB = [54, 66, 198, 114]   # передбачена рамка (prediction)

score = bb_intersection_over_union(boxA, boxB)
print(f"IoU: {score:.4f}")  # Очікуємо ~0.7980
```


| Параметр     | Тип         | Опис                                        |
| ------------ | ----------- | ------------------------------------------- |
| `boxA`       | `list[int]` | Перша рамка: `[x_min, y_min, x_max, y_max]` |
| `boxB`       | `list[int]` | Друга рамка: `[x_min, y_min, x_max, y_max]` |
| **Повертає** | `float`     | Значення IoU від 0.0 до 1.0                 |


> **Очікуваний вивід:** `IoU: 0.7980` — значення > 0.5, тобто це «хороше» передбачення.

### 2.3 Fast R-CNN

Оригінальна стаття: [тема_7/R_CNN.pdf](R_CNN.pdf)

**Fast R-CNN** (2015, Росс Гіршик) вирішує головну проблему R-CNN: замість того, щоб пропускати кожен з ~2000 регіонів через CNN окремо, зображення проходить через CNN **лише один раз**.

![Fast R-CNN: архітектура — одна CNN, ROI Pooling, паралельні гілки](images/fast_rcnn_architecture.png)

*Fast R-CNN: зображення + ROI проекція → спільна CNN → ROI Pooling → класифікація і регресія*

#### Кроки Fast R-CNN

**Крок 1. Виділення ознак для всього зображення**

Вхідне зображення передається через **одну** базову CNN (VGG-16 або ResNet) → отримуємо **карту ознак** (feature map) для всього зображення.

> **Що таке VGG-16 і ResNet?**
>
> Це архітектури CNN, що використовуються як **backbone** — мережа, яка витягує ознаки із зображення.
>
> - **VGG-16** — Visual Geometry Group (Oxford). Число 16 = кількість шарів із навчуваними параметрами. Проста і надійна архітектура з послідовними Conv-шарами 3×3.
> - **ResNet** — Residual Network («залишкова мережа»). Ключова ідея: **skip connections** — сигнал може «перестрибувати» через кілька шарів. Це дозволяє будувати дуже глибокі мережі без деградації градієнтів.
>
> ```
> Image → VGG-16 / ResNet → feature map
> ```
>
> У Fast R-CNN backbone обробляє зображення **один раз** → feature map передається далі для всіх ROI.

**Крок 2. Генерація пропозицій регіонів**

Паралельно, використовуючи **Selective Search** (так само як у R-CNN), генеруються ~2000 регіонів-кандидатів. Їх координати проектуються на карту ознак.

> **Ключова відмінність від R-CNN:** регіони не обробляються CNN окремо — їх координати просто відображаються на вже готову feature map.

**Крок 3. ROI Pooling**

> **ROI = Region of Interest** — «область інтересу».
> Це конкретна ділянка зображення, яку Selective Search вважає потенційним об'єктом.

**ROI Pooling** перетворює регіон **довільного розміру** на тензор **фіксованого розміру** (наприклад, 7×7).

**Навіщо потрібен фіксований розмір?**

Region proposals мають різні розміри — одна рамка 50×30, інша 200×150. Але Fully Connected шари після ROI Pooling очікують вхід **однакового розміру**. ROI Pooling вирішує це:

```
ROI  50× 30 ──┐
ROI 200×150 ──┼──→ ROI Pooling → 7×7 (однаковий розмір)
ROI  90× 60 ──┘
```

**Що таке pooling?**

Pooling бере групу чисел і стискає її до меншого розміру. Для **max pooling** — залишається лише найбільше значення:

```
1  5       max pooling
3  2   →      5
```

Мета: зменшити розмір даних, зберегти найсильніші активації, здешевити подальші обчислення.

**Що є виходом ROI Pooling?**

Це **тензор числових ознак** (не нове зображення!). У реальному Fast R-CNN — тензор розміром **7 × 7 × 256**, де:

- `7` — висота після pooling
- `7` — ширина після pooling
- `256` — кількість **каналів** (feature maps)

Уяви це як стопку з 256 карт ознак, кожна розміром 7×7:

```
feature map 1   → 7 × 7
feature map 2   → 7 × 7
...
feature map 256 → 7 × 7
─────────────────────────
Разом: 7 × 7 × 256 = 12 544 числових значень
```

> **Звідки береться 256?** Не від ROI Pooling — він лише змінює просторові розміри (висоту і ширину). Кількість каналів приходить із попереднього CNN/RPN шару, який має **256 filters** → кожен filter створює одну feature map → **256 filters = 256 channels**.
>
> ```
> 256 filters → 256 feature maps → 256 channels
> ```
>
> В іншій архітектурі це може бути 512, 1024 тощо.

Спрощений приклад для 2×2 виходу:

```
Input ROI (частина feature map):    Output після ROI Pooling 2×2:

1  3  7  2                               6  7
4  6  2  1     →  ROI Pooling  →         9  6
8  5  3  4
2  9  6  1
```

Ці числа — активації, які backbone CNN вже знайшов у feature map.

##### Як працює ROI Pooling — покроковий приклад

Маємо карту ознак розміром **8×8** і хочемо отримати вихід розміром **2×2**.

**Вхідна карта ознак (Input Activation):**

![ROI Pooling: вхідна карта ознак 8x8](images/roi_input_activation.jpg)

**Регіон пропозиції (Region Proposal):**

Координати: лівий верхній кут `(0, 3)`, висота = 5, ширина = 7 (рядки 3–7, колонки 0–6).

![ROI Pooling: виділений регіон пропозиції на карті ознак](images/roi_region_proposal.jpg)

**Ділення на секції для пулінгу (Pooling Sections):**

Регіон 5×7 ділиться на **2×2 = 4** приблизно однакові частини:

![ROI Pooling: поділ регіону на 4 секції](images/roi_pooling_sections.jpg)

**Результат після max pooling (вихід 2×2):**

З кожної секції обирається максимальне значення:

![ROI Pooling: результат 2x2 після max pooling](images/roi_pooling_output.png)

*Результат: 0.81 | 0.85 / 0.93 | 0.94 — чотири максимуми зі своїх секцій*

> **Чому це важливо:** незалежно від того, чи регіон 50×30 пікселів, чи 200×100 — після ROI Pooling ми завжди отримуємо тензор **7×7** (або будь-який фіксований розмір). Це дозволяє обробляти всі регіони однаковим FC-шаром.

**Крок 4. Класифікація та регресія (паралельно)**

Після ROI Pooling два паралельних виходи:

- **Classification head** — softmax по всіх класах + фон
- **Regression head** — поправки `(dx, dy, dw, dh)` до bounding box

**Крок 5. NMS**

Аналогічно R-CNN — видалення дублікатів рамок (алгоритм описаний у розділі 2.1).

**Повна схема Fast R-CNN:**

```
IMAGE
   ↓
CNN backbone (VGG-16 / ResNet)  ←─── обробляє зображення ОДИН РАЗ
   ↓
FEATURE MAP
   ↑
Selective Search
(~2000 region proposals)
   ↓
ROI Pooling
(усі ROI → однаковий фіксований розмір)
   ↓
Fully Connected layers
   ↓
       ┌──────────────────┐
       │                  │
 Classification      Bounding box
   (softmax)          regression
       │                  │
       └────────┬─────────┘
                ↓
               NMS
                ↓
       FINAL DETECTIONS
```

> **Головна відмінність від R-CNN:** у R-CNN CNN запускалась **окремо для кожного з ~2000 region proposals**. У Fast R-CNN CNN обробляє **все зображення один раз**, а різні ROI беруться вже з готової feature map.

#### Що покращив Fast R-CNN


| Аспект                     | R-CNN                | Fast R-CNN                    |
| -------------------------- | -------------------- | ----------------------------- |
| CNN-проходів на зображення | ~2000                | 1                             |
| Класифікатор               | Окремий SVM          | Softmax в мережі (end-to-end) |
| Тренування                 | Три незалежних кроки | Одне наскрізне тренування     |
| Час inference              | ~49 сек/зображення   | ~2 сек/зображення             |


> **Залишкова проблема:** Selective Search все ще виконується поза мережею — це **вузьке місце** (bottleneck). Faster R-CNN вирішує і цю проблему.

### 2.4 Faster R-CNN

Оригінальна стаття: [тема_7/Fast_R_CNN.pdf](Fast_R_CNN.pdf)

**Faster R-CNN** (2015) усуває останній недолік Fast R-CNN: замість зовнішнього **Selective Search** вводить **Region Proposal Network (RPN)** — частину нейромережі, яка сама знаходить потенційні області з об'єктами.

> **Простіше кажучи:**
>
> `Faster R-CNN = RPN + Fast R-CNN`
>
> - **RPN** — знаходить, *де можуть бути об'єкти*
> - **Fast R-CNN** — визначає, *що це за об'єкти*, і уточнює bounding boxes

![Faster R-CNN: архітектура з Conv layers, RPN, Feature maps та ROI pooling](images/faster_rcnn_architecture.png)

*Faster R-CNN: Conv layers → Feature maps → RPN (пропозиції) + ROI Pooling → класифікатор*

![Faster R-CNN: покрокова схема — що відбувається і що обчислюється](images/faster_rcnn_full_pipeline.jpg)

*Покрокова схема Faster R-CNN: Backbone CNN → Feature map → RPN (anchor boxes, NMS) → ROI Pooling (7×7×256) → Fast R-CNN head → клас + bounding box*

#### Архітектура Faster R-CNN

```
Зображення
     ↓
Backbone CNN (ResNet, VGG)   ← витягує ознаки
     ↓
Feature Map (спільна для RPN і детектора)
   ↙                    ↘
RPN                     ROI Pooling
(де об'єкти?)               ↓
     ↓               FC layers
  Proposals          ↙           ↘
     └──────→  Classification  BBox Regressor
                    ↓
                   NMS
                    ↓
            FINAL DETECTIONS
```

---

#### Backbone CNN — що це?

**Backbone** (буквально «хребет») — основна CNN, на якій «тримається» вся архітектура.

```
         RPN
        ↗
Backbone
        ↘
       Detector (Fast R-CNN)
```

Backbone приймає зображення і перетворює його на **feature maps** — числові матриці, що кодують:

- краї і текстури (ранні шари)
- форми і частини об'єктів (середні шари)
- складні патерни (глибокі шари)

Задача backbone — не сказати «це собака», а витягти корисні ознаки, якими скористаються і RPN, і детектор. Типові backbone: **ResNet-50, ResNet-101, VGG-16**.

---

#### Region Proposal Network (RPN)

RPN — легка нейромережа, яка **ковзає** по feature map і для кожної позиції прогнозує набір потенційних об'єктів.

![RPN: sliding window + anchor boxes → 2k scores + 4k coordinates](images/rpn_sliding_window.png)

*Ковзне вікно по feature map → 256-d вектор → cls layer (2k балів) і reg layer (4k координат) для k якорів*

---

**1. Anchor Boxes (якорі)**

**Anchor box — заздалегідь заданий прямокутник-шаблон**, що ставиться в кожній точці feature map.

Anchor — це ще **не знайдений об'єкт**, а гіпотеза:

> «А раптом тут є об'єкт приблизно такого розміру і форми?»

У кожній позиції RPN «примірює» k різних якорів:

```
□   маленький квадрат (1:1)
▯   вертикальний прямокутник (1:2)
▭   горизонтальний прямокутник (2:1)
... і ще кілька масштабів
```

У класичному Faster R-CNN:

- Масштаби: 128², 256², 512² пікселів
- Пропорції: 1:1, 1:2, 2:1

**3 масштаби × 3 пропорції = 9 якорів** у кожній позиції.

Якорі задаються вручну. Далі RPN передбачає **поправки** до кожного якоря:

```
anchor → regression offsets (dx, dy, dw, dh) → proposal
```

---

**2. Sliding Window = згорткове ядро 3×3**

**Sliding window** у контексті RPN — це сам процес руху ядра по feature map.

```
feature map              ядро 3×3 рухається:

[ ][ ][ ][ ]         [ ][ ][ ][ ]
[ ][■][■][ ]    →    [ ][ ][■][■]
[ ][■][■][ ]         [ ][ ][■][■]
[ ][ ][ ][ ]         [ ][ ][ ][ ]
```

RPN застосовує **згорткове ядро 3×3** до feature map — це і є ковзне вікно. Один крок:

```
вікно 3×3 на feature map
        ↓
z = w₁x₁ + w₂x₂ + ... + w₉x₉ + b   (навчувані ваги)
        ↓
256-d feature vector
```

**Чому 3×3?** Це хороший компроміс: бачить локальний контекст і сусідні значення, мало параметрів, швидко рахується. Важливо: хоча ядро лише 3×3 **на feature map**, його **receptive field на оригінальному зображенні** значно більший — backbone вже кілька разів застосував convolution і pooling.

---

**3. Дві гілки: cls layer і reg layer**

Для кожної позиції ковзного вікна 256-d вектор надходить у дві паралельні гілки:

```
256-d feature vector
     ↓
  ┌──────────────────┐
  │                  │
cls layer         reg layer
  │                  │
2k scores         4k coordinates
```

**Classification branch (cls layer):**

Для кожного з k якорів — два числа: object vs background:

```
anchor 1 → 0.92 (object)    0.08 (background)
anchor 2 → 0.15 (object)    0.85 (background)
anchor 3 → 0.73 (object)    0.27 (background)
```

Це і є **objectness score**.

Тому загальний вихід: **2 × k scores**.

**Regression branch (reg layer):**

Для кожного якоря — 4 поправки до координат:

```
dx  (зміщення центру по x)
dy  (зміщення центру по y)
dw  (зміна ширини)
dh  (зміна висоти)
```

Тому загальний вихід: **4 × k coordinates**.

Для стандартного k=9:

```
cls layer:  2 × 9 = 18 значень
reg layer:  4 × 9 = 36 значень
```

---

**4. Як навчається RPN?**

Під час тренування кожен anchor порівнюється з ground truth bounding boxes через IoU:

```
IoU великий (> 0.7)  →  positive anchor  →  тут є об'єкт
IoU маленький (< 0.3) → negative anchor  →  фон
```

Loss навчає ваги так, щоб позитивні якорі мали високий objectness score, а поправки координат наближали якір до реального об'єкта.

---

**5. Objectness Score (оцінка об'єктності)**

Objectness score — ймовірність того, що якір містить об'єкт (будь-який, незалежно від класу). Якорі з високим score передаються далі як proposals.

> **Важливо:** RPN **не розпізнає клас** об'єкта — лише каже «тут щось є» або «тут фон». Клас визначає вже Fast R-CNN на наступному кроці.

---

**6. NMS у RPN**

Після генерації тисяч proposals (всі позиції × 9 якорів) NMS залишає топ-**300** найкращих за objectness score.

---

**Повна схема RPN:**

```
IMAGE
  ↓
BACKBONE CNN
  ↓
FEATURE MAP
  ↓
3×3 sliding convolution (для кожної точки feature map)
  ↓
256-d feature vector  ← 256 = кількість filters у проміжному conv шарі RPN
  ↓                         (не від ROI Pooling; звідси ж береться "256" у 7×7×256)
для кожного з k anchors:
   ├─ objectness score (object / background)
   └─ 4 поправки координат (dx, dy, dw, dh)
  ↓
тисячі proposals
  ↓
NMS → топ-300 найкращих
  ↓
REGION PROPOSALS → Fast R-CNN
```

> **Ключова ідея:** anchor — це не результат, а **стартова рамка**, яку RPN оцінює і коригує.

---

#### Що покращив Faster R-CNN


| Аспект                   | Fast R-CNN                              | Faster R-CNN                  |
| ------------------------ | --------------------------------------- | ----------------------------- |
| Генерація пропозицій     | Selective Search (~2 сек, поза мережею) | RPN (< 10 мс, частина мережі) |
| Чи навчається генерація? | Ні                                      | Так — разом з детектором      |
| Час inference            | ~2 сек/зображення                       | ~0.1–0.2 сек/зображення       |
| Архітектура              | Частково end-to-end                     | Повністю end-to-end           |

## ЧАСТИНА 3. ОДНОЕТАПНІ АРХІТЕКТУРИ

### 3.1 YOLO (You Only Look Once)

Оригінальна стаття: [тема_7/YOLO.pdf](YOLO.pdf)

**YOLO** — перший масово популярний одноетапний детектор. Все зображення обробляється **одним проходом** через мережу, яка одночасно передбачає і класи, і координати рамок для всіх об'єктів.

> **Головна ідея одним реченням:**
> подивився на все зображення **один раз** → одразу сказав, **де об'єкти і що це за об'єкти**.

Порівняй з Faster R-CNN:

```
Faster R-CNN:              YOLO:
  image                      image
    ↓                          ↓
  backbone                    CNN
    ↓                          ↓
  RPN                       feature map
    ↓                          ↓
  proposals              одразу все:
    ↓                    - bounding boxes
  ROI Pooling            - confidence
    ↓                    - classes
  classifier                   ↓
    ↓                         NMS
  result                       ↓
                            result
```

Тому він і називається **You Only Look Once** — один прохід, одразу детекція.

#### Ідея: S×S сітка

![YOLO: сітка S×S + bounding boxes + class probability map → final detections](images/yolo_detection_pipeline.jpg)

*YOLO: зображення → S×S сітка → bounding boxes + confidence → class probability map → фінальні детекції*

**Алгоритм:**

1. Зображення масштабується до фіксованого розміру (448×448 або 416×416)
2. CNN витягує ознаки (краї, текстури, форми, частини об'єктів) — так само як backbone у Faster R-CNN
3. Ділиться на **S×S** сітку (наприклад, 7×7)
4. Кожна комірка сітки відповідає за виявлення об'єктів, центр яких знаходиться в цій комірці

```
┌───┬───┬───┬───┐
│   │   │   │   │
├───┼───┼───┼───┤
│   │ 🐶│   │   │   ← центр собаки тут → ця клітинка "відповідає" за собаку
├───┼───┼───┼───┤
│   │   │   │🐱 │   ← центр кота тут → ця клітинка "відповідає" за кота
└───┴───┴───┴───┘
```

> **Ключове правило:** за об'єкт відповідає та клітинка, в якій знаходиться **центр** об'єкта. Сам об'єкт може виходити за межі клітинки — рамка це дозволяє.

#### Структура передбачень

**Кожна комірка сітки** передбачає:

- **B** bounding boxes, кожна описується 5 числами: x, y, w, h, confidence
- **C** ймовірностей класів: P(Classᵢ | Object)

```
Confidence = P(Object) × IoU(pred, truth)
```

де IoU(pred, truth) — значення IoU між передбаченою і реальною рамкою.

**Числовий приклад — що видає одна клітинка:**

```
Bounding box:
  x = 0.6    ← центр рамки по горизонталі (відносно клітинки, 0–1)
  y = 0.4    ← центр рамки по вертикалі
  w = 0.3    ← ширина рамки (відносно всього зображення)
  h = 0.5    ← висота рамки
  confidence = 0.92   ← модель впевнена, що тут є об'єкт і рамка хороша

Class probabilities (окремо від bbox):
  dog    0.85
  cat    0.05
  person 0.02
  ...
```

**Фінальний score класу** = confidence × P(class | object):

```
dog score = 0.92 × 0.85 ≈ 0.78  →  "dog 78%"
```

**Confidence детально:**

- Якщо об'єкта немає → `confidence ≈ 0`
- Якщо є об'єкт і рамка ідеальна (IoU=1) → `confidence = P(object) × 1.0` → максимум
- Тобто confidence штрафує одночасно за відсутність об'єкта і за погану рамку

#### Формат bounding box


| Параметр   | Опис                                                                  |
| ---------- | --------------------------------------------------------------------- |
| x, y       | Координати центру рамки відносно меж комірки (від 0 до 1)             |
| w, h       | Ширина і висота рамки відносно розміру всього зображення (від 0 до 1) |
| confidence | P(Object) × IoU — впевненість в наявності об'єкта                     |


#### Формат вихідного тензора

```
Output shape = S × S × (B × 5 + C)
```

Для оригінального YOLO v1: S=7, B=2, C=20 (Pascal VOC) → вихід **7×7×30**


| Символ | Значення             | Пояснення                           |
| ------ | -------------------- | ----------------------------------- |
| S      | 7                    | Розмір сітки                        |
| B      | 2                    | Кількість bounding boxes на комірку |
| 5      | фіксовано            | x, y, w, h, confidence              |
| C      | 20 (VOC) / 80 (COCO) | Кількість класів                    |


**Розгорнуто — що є у тих 30 числах однієї клітинки:**

```
2 bounding boxes × 5 параметрів = 10 чисел
  box 1: x, y, w, h, confidence
  box 2: x, y, w, h, confidence
+
20 class probabilities (dog, cat, car, person ...)
= 30 чисел
```

Отже весь вихід: **49 клітинок × 30 = 1470 чисел** в тензорі `7 × 7 × 30`.

> **Навіщо дві bounding boxes (B=2)?**
> Одна клітинка може запропонувати кілька варіантів рамки. Після навчання предиктори **спеціалізуються**: один може краще ловити широкі горизонтальні об'єкти, інший — вузькі вертикальні. Під час навчання за кожний ground truth відповідає той bbox, у якого вищий IoU. Решта вважається "no object".

#### Архітектура мережі (YOLOv1)

![YOLO: архітектура Darknet — Conv шари + FC шари](images/yolo_architecture_1.png)

*YOLOv1 backbone: 24 згорткових шари + 2 повнозв'язних. Вхід 448×448 → вихід 7×7×30*

**Блоки архітектури:**

- Conv Layer 7×7×64, stride=2 → MaxPool 2×2, stride=2 → `112×112×192`
- Conv Layer 3×3×192 → MaxPool 2×2, stride=2 → `56×56×256`
- Блоки 1×1 + 3×3 (зменшення розміру + виявлення ознак) → `28×28×512`
- ... → `14×14×1024` → `7×7×1024`
- FC 4096 → FC 7×7×30 (вихід)

> **Нагадування — Inception та натхнення YOLOv1:**
> YOLOv1 **натхненний** архітектурою **GoogLeNet/Inception** від Google, але не копіює її один в один. В оригінальній статті YOLO блоки `1×1 + 3×3` запозичені саме з ідеї Inception — паралельна обробка feature map фільтрами різного розміру:
>
> ```
> input feature map
>    ├─ 1×1 conv   ← дрібні деталі, зменшення глибини
>    ├─ 3×3 conv   ← середній масштаб
>    ├─ 5×5 conv   ← великий контекст
>    └─ pooling
>         ↓
>    concatenate   ← модель одночасно бачить ознаки різного масштабу
> ```
>
> Ідея: замість вибору «який розмір фільтра кращий?» — застосувати всі й об'єднати результати.

#### Функція втрат YOLO

YOLO мінімізує суму трьох компонентів:

`L = L_coord + L_obj + L_class`


| Компонент | Що вимірює                                   |
| --------- | -------------------------------------------- |
| `L_coord` | Точність координат (x, y, w, h) bounding box |
| `L_obj`   | Точність confidence (чи є об'єкт у рамці)    |
| `L_class` | Точність ймовірностей класів                 |


Схематично:

```
неправильна рамка          неправильний confidence       неправильний клас
(x, y, w, h)                 (є/немає об'єкт)
       ↓                            ↓                            ↓
  L_coord                       L_obj                       L_class
       └────────────────────────────┴────────────────────────────┘
                                   ↓
                              загальний L
                                   ↓
                           backpropagation
                                   ↓
                         оновлення weights
```

> **Важливо:** координати √w і √h — корінь з ширини і висоти. Це зменшує вплив великих рамок і дозволяє однаково штрафувати за помилки в маленьких і великих об'єктах.

#### NMS після YOLO

YOLO може знайти один об'єкт кількома рамками (від різних клітинок або bbox):

```
┌────────────┐
│ ┌────────┐ │
│ │  🐶    │ │   box A → dog 0.95
│ └────────┘ │   box B → dog 0.89  ← перекривається з A
└────────────┘   box C → dog 0.72  ← теж перекривається
```

NMS дивиться на IoU між рамками і вирішує: "це один і той самий об'єкт" → залишає найкращу:

```
box A → 0.95  ✓  залишається
box B → 0.89  ✗  пригнічується (IoU з A > порогу)
box C → 0.72  ✗  пригнічується (IoU з A > порогу)
```

Після прогнозу S×S×(B×5+C) тензора:

1. Відфільтрувати рамки з confidence < порогу (наприклад, 0.5)
2. Для кожного класу застосувати NMS (алгоритм описаний вище)
3. Залишаються лише рамки з найвищими confidence і мінімальним перекриттям

#### Еволюція YOLO


| Версія | Рік  | Ключові нововведення                                                      |
| ------ | ---- | ------------------------------------------------------------------------- |
| YOLOv1 | 2016 | Перший одноетапний YOLO, сітка S×S                                        |
| YOLOv2 | 2017 | Darknet-19, anchor boxes, Batch Normalization, багатомасштабне тренування |
| YOLOv3 | 2018 | Darknet-53, багаторівнева детекція (3 масштаби), резидуальні зв'язки      |
| YOLOv4 | 2020 | CSPDarknet, Mosaic аугментація, CIoU loss                                 |
| YOLOv5 | 2020 | PyTorch-реалізація Ultralytics, простота розгортання                      |
| YOLOv8 | 2023 | Нова архітектура Ultralytics, декілька задач (detect/segment/pose)        |
| YOLOv9 | 2024 | GELAN архітектура, PGI (Programmable Gradient Information)                |


**Ключові покращення між версіями:**

- **Anchor boxes** (v2+) — попередньо задані форми рамок замість прямого прогнозу → краща локалізація
- **Batch Normalization** (v2+) — стабілізує навчання, зменшує потребу в Dropout
- **Backbone Darknet-53** (v3) — глибша і точніша основа з residual зв'язками
- **Мульти-масштабна детекція** (v3+) — три різні масштаби для виявлення об'єктів різних розмірів
- **Mosaic аугментація** (v4+) — комбінація 4 зображень в одне → більше різноманіття для навчання
- **IoU-based loss** (v4+) — GIoU / DIoU / CIoU замість MSE для координат

> **Нагадування — що таке Darknet:**
> **Darknet** — це не окремий шар, а **CNN-архітектура (backbone)**, спеціально розроблена для YOLO. Різні версії YOLO мають різні backbone:
>
>
> | Версія YOLO | Backbone                                                    |
> | ----------- | ----------------------------------------------------------- |
> | YOLOv2      | Darknet-19 (19 convolutional layers)                        |
> | YOLOv3      | Darknet-53 (53 convolutional layers + residual connections) |
> | YOLOv4      | CSPDarknet                                                  |
>
>
> Наприклад, **Darknet-53** — глибока мережа з residual зв'язками, схожа за ідеєю на ResNet. Загальний пайплайн:
>
> ```
> Image
>   ↓
> Darknet backbone   ← витягує ознаки (те саме, що ResNet у Faster R-CNN)
>   ↓
> Feature maps
>   ↓
> YOLO detection head
>   ↓
> boxes + classes
> ```
>
> Починаючи з YOLOv5/v8, Ultralytics перейшов з Darknet на власні backbone на базі PyTorch.

### 3.2 RetinaNet

Оригінальна стаття: [тема_7/Retina_Net.pdf](Retina_Net.pdf)

**RetinaNet** (2017, Facebook AI Research) — одноетапний детектор, який вирішує головний недолік одноетапних підходів: **дисбаланс класів**.

#### Проблема дисбалансу класів

В одному зображенні може бути **тисячі** фонових регіонів і **лише 3–5** об'єктів. При стандартній крос-ентропії модель «ліниво» вчиться класифікувати все як фон — це дає низький loss, але марну модель.


| Наслідок дисбалансу   | Що відбувається                                                     |
| --------------------- | ------------------------------------------------------------------- |
| Переважання фону      | Більшість градієнтів — від «легкого» фону, а не від важких об'єктів |
| Необ'єктивне навчання | Модель оптимізує loss за рахунок фону, ігноруючи рідкісні класи     |
| Зниження точності     | Пропускає важливі об'єкти або дає хибні спрацювання                 |


**Рішення RetinaNet:** Focal Loss.

#### Архітектура RetinaNet

![RetinaNet: ResNet + FPN + class subnet + box subnet](images/retinanet_architecture.png)

*RetinaNet: (a) ResNet backbone → (b) FPN → (c) classification subnet + (d) box subnet*

![RetinaNet: повна схема з розмірами, FPN, Focal Loss, Classification та Box Regression subnet](images/retinanet_full_pipeline.jpg)

*Повна покрокова схема RetinaNet: вхідне зображення → ResNet (C2–C5) → FPN (P2–P5) → Classification Subnet + Box Regression Subnet → NMS → фінальні детекції*

> **Примітка про схему:** в оригінальній статті RetinaNet використовує рівні **P3–P7** (P6 і P7 додаються зверху P5 через strided convolution). Схема спрощено показує P2–P5 — архітектурна логіка однакова.

**Компоненти:**

**1. Backbone: ResNet**

ResNet-50 або ResNet-101 для виділення ознак на різних рівнях. Для вхідного зображення 800×1333 (H×W×3):


| Рівень | Розмір карти ознак | Channels | Масштаб відносно входу                              |
| ------ | ------------------ | -------- | --------------------------------------------------- |
| C2     | 192 × 320          | 256      | 1/4 — висока роздільна здатність, мало семантики    |
| C3     | 96 × 160           | 512      | 1/8                                                 |
| C4     | 48 × 80            | 1024     | 1/16                                                |
| C5     | 24 × 40            | 2048     | 1/32 — низька роздільна здатність, багато семантики |


> **Зв'язок з backbone:** чим глибший шар → тим менша карта ознак, але тим більше каналів і багатша семантика (модель «розуміє» складніші ознаки).

**2. Feature Pyramid Network (FPN)**

![FPN: Bottom-Up Pathway + Top-Down Pathway + Lateral Connections](images/fpn_architecture.png)

*FPN: знизу вверх (низькорівневі ознаки) + зверху вниз (семантичні ознаки) + бокові зв'язки*

Оригінальна стаття FPN: [тема_7/Feature_Pyramid_Network.pdf](Feature_Pyramid_Network.pdf)

**FPN (Feature Pyramid Network)** вирішує проблему виявлення об'єктів різних масштабів.

**Bottom-Up Pathway (висхідний шлях):**

- Звичайне проходження через ResNet
- На кожному рівні отримуємо карту ознак з різною роздільною здатністю
- Нижні рівні = висока роздільна здатність + слабка семантика
- Верхні рівні = низька роздільна здатність + сильна семантика

**Top-Down Pathway (низхідний шлях) + Lateral Connections:**

- Починаємо з верхнього (семантично сильного) рівня C5
- `1×1 conv` зменшує кількість каналів у C2–C5 до **256**
- З вищого рівня (наприклад, P5) ознаки збільшуються у 2 рази (upsampling)
- Поелементно додаються (`⊕`) до lateral connection з відповідного нижнього рівня
- Результат: карта ознак з **семантикою** (зверху) + **деталями** (знизу)

```
C5 → 1×1 conv → P5 (24×40×256)
                    ↓ 2× up
C4 → 1×1 conv → ⊕ → P4 (48×80×256)
                    ↓ 2× up
C3 → 1×1 conv → ⊕ → P3 (96×160×256)
                    ↓ 2× up
C2 → 1×1 conv → ⊕ → P2 (192×320×256)
```

**Результат:** карти ознак P2–P5, кожна **256 channels**, різна роздільна здатність, кожна семантично сильна → виявлення об'єктів усіх розмірів.

> **Навіщо 1×1 conv зменшує канали?** Щоб зробити всі рівні P2–P5 однакової глибини (256), що спрощує подальші шари.

**3. Anchor Boxes**

На кожній точці карт ознак — A якорів з різними масштабами і співвідношеннями сторін:

- 3 масштаби × 3 співвідношення сторін = **9 якорів на позицію**
- Ці самі якорі використовуються для classification і regression subnets

**4. Classification Subnet (підмережа класифікації)**

```
Pᵢ (H × W × 256)
   ↓
4 × Conv 3×3, 256ch, ReLU
   ↓
Conv 3×3, A×K ch
   ↓
H × W × (A × K)   ← ймовірності класів для кожного якоря
```

- Однакова архітектура (спільні ваги) на **всіх рівнях** FPN
- Останній шар видає A×K значень (A — кількість якорів, K — кількість класів)
- Активація — **sigmoid** (не softmax), бо класи **не взаємовиключні** (один об'єкт може бути і "dog" і "animal")

**5. Box Regression Subnet (підмережа регресії)**

```
Pᵢ (H × W × 256)
   ↓
4 × Conv 3×3, 256ch, ReLU
   ↓
Conv 3×3, 4×A ch
   ↓
H × W × (4 × A)   ← координати рамок (dx, dy, dw, dh) для кожного якоря
```

Аналогічна архітектура: 4 шари 3×3, 256. Останній шар — 4×A координати (зсуви відносно якоря).

#### Focal Loss

Головна інновація RetinaNet — функція втрат **Focal Loss**.

> **Назва:** "focal" = **focus / зосередження** (не геометричний фокус). Ідея: функція втрат **фокусується** на складних прикладах і майже ігнорує легкі.

---

##### Крок 0. Що таке Cross-Entropy (CE)

Перш ніж розуміти Focal Loss, потрібно зрозуміти Cross-Entropy — вона є його основою.

**Cross-entropy** вимірює, наскільки передбачені моделлю ймовірності відрізняються від правильної відповіді. Для правильного класу:

```
CE = -log(pₜ)
```

де `pₜ` — ймовірність, яку модель дала **правильному** класу.

**Числовий приклад.** Правильний клас — `cat`:

```
Приклад A (модель впевнена):        Приклад B (модель плутається):
cat = 0.9                            cat = 0.1
dog = 0.07                           dog = 0.8
car = 0.03                           car = 0.1

CE = -log(0.9) ≈ 0.105  ← малий    CE = -log(0.1) ≈ 2.303  ← великий
```

Тобто CE великий, коли модель **помиляється або сумнівається**, і малий — коли **впевнена і права**.

---

##### Крок 0.5. Що таке логарифм у цьому контексті

Логарифм відповідає на питання: **до якого степеня треба піднести основу, щоб отримати це число?**

У ML зазвичай натуральний логарифм (основа `e ≈ 2.718`). Для ймовірностей від 0 до 1 — він завжди **від'ємний**, тому перед ним стоїть мінус:

```
-log(0.99) ≈ 0.01   ← дуже малий: модель майже ідеальна
-log(0.9)  ≈ 0.105
-log(0.5)  ≈ 0.693
-log(0.1)  ≈ 2.303
-log(0.01) ≈ 4.605  ← дуже великий: модель впевнено помилилась
```

Саме тому CE добре **карає впевнені помилки** — чим менше `pₜ`, тим більший loss.

---

##### Крок 1. Формула Focal Loss

**Базова форма:**
```
FL(pₜ) = -(1 - pₜ)^γ · log(pₜ)
```

**З α-балансуванням (використовується на практиці):**
```
FL(pₜ) = -αₜ · (1 - pₜ)^γ · log(pₜ)
```

де:
- **pₜ** — ймовірність правильного класу (після sigmoid)
- **γ (gamma)** — **гіперпараметр** фокусування, зазвичай γ=2 (задається вручну, не вчиться)
- **(1-pₜ)^γ** — **штучно введений weighting factor** (модулюючий множник)
- **αₜ** — ваговий коефіцієнт для балансування позитивних/негативних прикладів (часто α=0.25)

Focal Loss — це Cross-Entropy, до якої **додали** множник `(1-pₜ)^γ`:
```
FL = (1 - pₜ)^γ  ×  CE
         ↑               ↑
  зменшує легкі    звична cross-entropy
```

---

##### Крок 2. Як працює модулюючий множник

**Легкий приклад** (модель вже добре його класифікує, `pₜ` велике):
```
pₜ = 0.95, γ = 2:
(1 - 0.95)² = 0.05² = 0.0025   ← множник дуже малий
```
Loss цього прикладу множиться на `0.0025` → майже не впливає на навчання.

**Складний приклад** (модель плутається, `pₜ` мале):
```
pₜ = 0.20, γ = 2:
(1 - 0.20)² = 0.80² = 0.64   ← множник великий
```
Loss майже не пригнічується → приклад залишається важливим.

**Підсумок:**
```
pₜ близьке до 1  →  (1-pₜ)^γ → 0  →  loss "гаситься"    →  легкий приклад ігнорується
pₜ мале          →  (1-pₜ)^γ → 1  →  loss майже не змінюється  →  складний залишається важливим
```

> **Важливе уточнення:** γ **зменшує вагу легких прикладів**, а не напряму "збільшує штраф" за складні. Складні приклади залишаються важливими тому, що їх НЕ пригнічують.

---

##### Крок 3. Easy і Hard examples

| | Що це | Приклад у детекції |
|---|---|---|
| **Easy example** | Модель впевнена і права (`pₜ ≈ 0.99`) | Чисте небо → "background", стіна без об'єктів → "background" |
| **Hard example** | Модель сумнівається або помиляється (`pₜ ≈ 0.1–0.3`) | Дрібний об'єкт, частково перекритий, або незвичний кут |

У RetinaNet є тисячі **easy background** ділянок. При звичайній CE їхня сумарна помилка **домінує** просто через кількість, і модель «лінується» на складних об'єктах. Focal Loss вирішує це:

> «Не витрачай стільки уваги на фон, який ти вже добре розпізнаєш. Зосередься на складних об'єктах.»

---

##### Крок 4. Роль γ

| γ | Ефект |
|---|---|
| γ = 0 | FL ≡ Cross Entropy (множник = 1, нічого не змінюється) |
| γ = 1 | Легкі приклади приглушуються помірно |
| γ = 2 | Легкі приглушуються суттєво — **рекомендоване значення** у RetinaNet |
| γ > 2 | Ще сильніше ігнорує легкі; ризик пропустити деякі корисні сигнали |

---

**Порівняння CE Loss та Focal Loss:**

| | Cross Entropy | Focal Loss (γ=2) |
|---|---|---|
| Легкий фоновий приклад (pₜ=0.9) | Все ще вносить loss | Loss ≈ 0 |
| Складний об'єкт (pₜ=0.1) | Вносить loss | Вносить ще більший відносний loss |
| **Результат** | Домінує фон | Фокус на важких прикладах |


#### Переваги RetinaNet


| Перевага                      | Пояснення                                          |
| ----------------------------- | -------------------------------------------------- |
| Focal Loss                    | Ефективно справляється з дисбалансом класів        |
| FPN (Feature Pyramid Network) | Виявляє об'єкти різних масштабів на одному проході |
| Одноетапний                   | Швидший за двоетапні при порівнянній точності      |

---

### Що в них спільного

Майже всі сучасні детектори мають одну базову ідею:

```
IMAGE
  ↓
CNN / BACKBONE        ← витягує ознаки (краї, текстури, форми)
  ↓
FEATURE MAPS
  ↓
визначити:
- де об'єкт?          ← localization / box regression
- що це за об'єкт?   ← classification
  ↓
BOUNDING BOX + CLASS
```

Тобто всі вони роблять дві задачі:
1. **Classification** — що це?
2. **Localization / Box regression** — де це?

**Backbone у всіх виконує одну функцію:**

```
pixels → edges → textures → shapes → higher-level features
```

Перетворити зображення на **feature maps**. Конкретна архітектура (ResNet, VGG, Darknet) — деталь реалізації.

---

### Головна різниця: one-stage vs two-stage

```
Two-stage (Faster R-CNN):        One-stage (YOLO, RetinaNet):

Image                             Image
  ↓                                 ↓
Backbone                          CNN / Backbone
  ↓                                 ↓
RPN                              Feature maps
  ↓                                 ↓
Region proposals               boxes + classes (одразу)
  ↓
Classifier + box regression
```

- **Two-stage**: спочатку «де приблизно є об'єкти?», потім «що це?» → точніше, але повільніше
- **One-stage**: один прохід, все одразу → швидше, але складніше збалансувати точність

---

### Еволюція R-CNN → Fast R-CNN → Faster R-CNN

Найпростіша мнемоніка:

```
R-CNN
  CNN запускається окремо для кожного з ~2000 proposals
  → дуже повільно
       ↓
Fast R-CNN
  CNN рахується один раз для всього зображення
  Але Selective Search залишився (зовнішній, повільний)
       ↓
Faster R-CNN
  Прибрали Selective Search
  Замінили на RPN — нейромережа сама знаходить proposals
  → повністю end-to-end
```

---

### Хто що додав — коротка шпаргалка

| Модель | Головна ідея |
|---|---|
| **R-CNN** | CNN для region proposals |
| **Fast R-CNN** | CNN один раз + ROI Pooling |
| **Faster R-CNN** | RPN замість Selective Search |
| **YOLO** | усе детектувати за один прохід |
| **RetinaNet** | one-stage + FPN + Focal Loss |

---

### Якщо вибирати концептуально

| Потреба | Типовий вибір |
|---|---|
| Максимальна точність важливіша за швидкість | **Faster R-CNN** |
| Real-time / швидка детекція | **YOLO** |
| One-stage + хороший баланс accuracy/speed | **RetinaNet / YOLO-сімейство** |
| Багато об'єктів різного масштабу | **RetinaNet з FPN** |
| Вивчити еволюцію object detection | **R-CNN → Fast → Faster** |

## ЧАСТИНА 4. ПОРІВНЯННЯ МОДЕЛЕЙ

### Еталонний датасет: COCO

**COCO (Common Objects in Context)** — стандартний датасет для порівняння детекторів:

- ~330,000 зображень, 80 класів
- Кожне зображення — кілька об'єктів різних розмірів
- Анотації: bounding boxes, маски сегментації, ключові точки

### Метрика: mAP (mean Average Precision)

**mAP = mean Average Precision** — загальна назва метрики для object detection. Залежно від того, що оцінюється:

- **Box mAP** — якість bounding boxes (стандарт для детекції)
- **Mask mAP** — якість segmentation masks (наприклад, у Mask R-CNN)

> Якщо модель робить лише детекцію рамок — `mAP` і `Box mAP` фактично означають одне й те саме.

**Коротко:** Box mAP = наскільки добре модель одночасно **знаходить правильні класи** об'єктів і **правильно ставить навколо них bounding boxes**.

---

#### Рівень 1. Чи правильна конкретна детекція — IoU і threshold

Для кожної передбаченої рамки рахуємо **IoU** з ground truth:

```
IoU = intersection / union
```

Якщо встановлений поріг `IoU ≥ 0.5`:
- перекриття достатнє → **True Positive (TP)**
- перекриття замале → **False Positive (FP)**

---

#### Рівень 2. Precision і Recall для одного класу

![Precision-Recall curve і mAP: від IoU до AP і mAP для object detection](images/precision_recall_map_explained.jpg)

*Повна схема: IoU → TP/FP → Precision-Recall крива → AP (площа під кривою) → mAP по класах → різні IoU пороги*

| Термін | Формула | Значення |
|---|---|---|
| **True Positive (TP)** | IoU ≥ поріг, правильний клас | Модель правильно знайшла об'єкт |
| **False Positive (FP)** | Рамка є, але IoU < порогу або неправильний клас | Хибне спрацювання |
| **False Negative (FN)** | Об'єкт є, але модель його пропустила | Пропуск об'єкта |

```
Precision = TP / (TP + FP)
```
> Серед того, що модель назвала собакою — скільки справді собак?

```
Recall = TP / (TP + FN)
```
> Серед усіх реальних собак — скільки модель знайшла?

**Як зміна confidence threshold впливає на Precision і Recall:**
- Знижуємо поріг → модель знаходить більше об'єктів → **Recall** зростає, але більше хибних → **Precision** падає
- Підвищуємо поріг → модель обережніша → **Precision** зростає, але пропускає більше → **Recall** падає

Precision і Recall рахуються при **різних confidence thresholds** → будується **Precision–Recall крива**.

**AP (Average Precision)** для одного класу = **площа під цією кривою**.

---

#### AP як інтеграл (і як він рахується на практиці)

Концептуально AP — це інтеграл:

```
AP = ∫₀¹ Precision(Recall) dRecall
```

Але крива складається з дискретних точок (по одній на кожен confidence threshold), тому на практиці площу рахують **чисельно** — як суму прямокутних ділянок:

```
AP ≈ Σ Precisionᵢ × (Recallᵢ - Recallᵢ₋₁)
```

де `(Recallᵢ - Recallᵢ₋₁)` — **ширина** ділянки по осі Recall, `Precisionᵢ` — **висота**.

**Числовий приклад:**

| Recall | Precision | Ширина ділянки (ΔRecall) | Внесок у AP |
|---|---|---|---|
| 0.2 | 1.0 | 0.2 - 0 = **0.2** | 1.0 × 0.2 = 0.200 |
| 0.5 | 0.9 | 0.5 - 0.2 = **0.3** | 0.9 × 0.3 = 0.270 |
| 0.8 | 0.7 | 0.8 - 0.5 = **0.3** | 0.7 × 0.3 = 0.210 |
| 1.0 | 0.5 | 1.0 - 0.8 = **0.2** | 0.5 × 0.2 = 0.100 |
| | | **Сума** | **AP ≈ 0.78** |

> **AP ≈ 0.78** — модель знаходить об'єкти добре, але не ідеально.

> **Важливий нюанс:** COCO використовує інтерпольовану Precision–Recall криву і оцінює precision у **101 recall point** від 0 до 1 — тому значення можуть трохи відрізнятись від наївного підрахунку.

---

#### Рівень 3. mAP — середнє AP по всіх класах

```
AP per class:
  dog → AP = 0.91
  cat → AP = 0.84
  car → AP = 0.76

mAP = (0.91 + 0.84 + 0.76) / 3 = 0.84  →  mAP = 84%
```

```
mAP = (1/C) × (AP₁ + AP₂ + ... + APc)
```

Назва буквально розкладається:
> **Precision → Average Precision для одного класу → mean Average Precision по класах**

---

#### mAP@0.5 vs mAP@0.5:0.95

| Метрика | Що означає | Суворість |
|---|---|---|
| **mAP@0.5** | Детекція правильна, якщо IoU ≥ 0.5 | М'який критерій |
| **mAP@0.5:0.95** | AP усереднюється по IoU від 0.50 до 0.95 з кроком 0.05 | Суворий критерій COCO |

**mAP@0.5:0.95** рахується при 10 різних порогах IoU: `0.50, 0.55, 0.60, ..., 0.95` — потім усереднюється. Модель має не лише знайти клас, а й **дуже точно поставити bounding box**.

**Числовий приклад з таблицею по класах (@0.5 vs @0.5:0.95):**

| Клас | AP (IoU = 0.5) | AP (IoU = 0.5:0.95) |
|---|---|---|
| dog | 0.91 | 0.68 |
| cat | 0.84 | 0.57 |
| car | 0.76 | 0.49 |
| **mAP** | **0.84** | **0.58** |

Різниця між `0.84` і `0.58` — цілком нормальна: перша каже «об'єкти знаходить добре», друга «але рамки не завжди дуже точні».

---

### Тенденції розвитку

З виходом нових архітектур:

- **Точність** (mAP) стабільно зростає від покоління до покоління
- **Швидкість** (FPS) покращується за рахунок ефективніших backbone і архітектурних рішень
- **YOLO-сімейство** залишається лідером у балансі швидкість/точність для edge-застосувань
- **Двоетапні підходи** (Cascade R-CNN та ін.) домінують у точності там, де швидкість не критична

### Випадкова візуалізація зображень

```python
def plot_random_images_from_folder(folder_path, num_images=20, seed=CFG.SEED):
    """
    Відображає сітку випадково обраних зображень з теки.
    
    folder_path: str — шлях до теки із зображеннями
    num_images:  int — скільки зображень показати
    seed:        int — seed для відтворюваності вибірки
    """
    random.seed(seed)  # Фіксуємо seed — завжди отримуємо однакову вибірку

    # Збираємо всі файли зображень у теці за відомими розширеннями
    image_files = [
        f for f in os.listdir(folder_path)
        if f.endswith(('.jpg', '.png', '.jpeg', '.gif'))
    ]

    if len(image_files) < num_images:
        raise ValueError("Not enough images in the folder")

    # Випадково обираємо num_images файлів (без повторення)
    selected_files = random.sample(image_files, num_images)

    # Розраховуємо розміри сітки: 5 стовпців, решта — рядки
    num_cols = 5
    num_rows = (num_images + num_cols - 1) // num_cols  # Округлення вгору
    fig, axes = plt.subplots(num_rows, num_cols, figsize=(12, 8))

    for i, file_name in enumerate(selected_files):
        img = Image.open(os.path.join(folder_path, file_name))

        # Вибираємо правильну вісь залежно від кількості рядків
        if num_rows == 1:
            ax = axes[i % num_cols]
        else:
            ax = axes[i // num_cols, i % num_cols]

| ---------- | -------------------- | -------------------------------------------------------- |

**Що таке ONNX?**

**ONNX (Open Neural Network Exchange)** — відкритий формат обміну моделями машинного навчання. Він дозволяє:

- Навчити модель у **PyTorch** (Ultralytics/YOLO)
- Розгорнути у **TensorFlow, TensorRT, OpenVINO, CoreML** та інших фреймворках
- Запустити на різних платформах: сервер, мобільний пристрій, IoT-пристрій, браузер

```
PyTorch (навчання) → .pt → [model.export()] → .onnx → будь-який runtime
```

## ПІДСУМКИ

### Що ми вивчили

- **Детекція об'єктів** — задача, що поєднує класифікацію (що?) і локалізацію (де?). Вихід: набір bounding boxes з класами і координатами.
- **Двоетапні підходи:**
  - **R-CNN** — Selective Search + окрема CNN для кожного регіону + SVM. Точно, але повільно.
  - **Fast R-CNN** — одна CNN для всього зображення + ROI Pooling. Значно швидше.
  - **Faster R-CNN** — заміна Selective Search на RPN. Повністю end-to-end.
- **Одноетапні підходи:**
  - **YOLO** — S×S сітка, один прохід, формат виходу S × S × (B × 5 + C). Реальний час.
  - **RetinaNet** — FPN + Focal Loss. Вирішує дисбаланс класів в одноетапному підході.
- **Ключові компоненти:**
  - **IoU** — метрика перекриття рамок: IoU = Overlap / Union
  - **Loss YOLO** = `L_coord + L_obj + L_class`
  - **NMS** — прибирає дублікати рамок, залишає найвпевненіші
  - **ROI Pooling** — нормалізує регіони різних розмірів до фіксованого тензора
  - **Anchor Boxes** — шаблони рамок різних форм і розмірів
  - **FPN** — піраміда ознак для виявлення об'єктів різних масштабів
  - **Focal Loss** — фокусує навчання на складних прикладах, а не на фоні
- **Практика:** налаштування YOLOv9 на датасеті будівельного майданчика — 10 класів засобів безпеки.
